# C4 pair score 的誤差模型（2026-10-26）

> **2026-11-04 註記：** 本實驗用到的 `2026-10-25_c4_robustness`（含 `sims/`）、`2026-10-26_c4_composite_weight`、`2026-10-26_sim_expectation_check` 已刪除。文中引用保留原文；重跑需要的模擬資料已不在。`c4_robustness` 可用 `git show db9fa20:lab_report/2026-10-25_c4_robustness/README.md` 取回 README，另外兩個未進 git，無法取回。

問題：把定序錯誤寫進 pair score（`--pair-error e`）之後，失效模式 1（clone 被拆開）會不會消失？會不會像 composite weight 一樣，讓 C1／C2 重新合併、模式 2 變嚴重？背景：`lab_report/2026-10-26_c4_composite_weight/`（固定 w 失敗）、`lab_report/2026-10-26_c4_truth_vs_map/`（模式 1 來自 pair term，模式 2 主要來自 FSCRP prior）。

標記：〔實測〕＝本實驗計算；〔推論〕＝本檔推論。

## 1. 結論

- **e 設成真實錯誤率時，模式 1 消失。** 〔實測〕b03（真實 base error 3%）用 e = 0.03：segment C 的相容比例從 0.55／0.46／0.38（eps 0.01）升到 1.00／1.00／0.99；clone 數眾數從 4／7／5 降到 3／3／3（真值收縮後 3–4）。
- **e 設成校正值 0.004 時，整體比 eps 0.01 好，但依判定門檻不算改善。** 〔實測〕「校正組合」：e0／real／sw5 用 0.004，b03 用 0.03，相當於從 normal 樣本量測錯誤率。和 eps 0.01 比較：
  - C1／C2 分開：10 vs 9 個 run；完整 4 clone 樹 > 0.5：3 vs 2；segment C 相容比例平均 0.943 vs 0.728。
  - 模式 2（real s2）：0.39 → 0.17。
  - 但 real s1 的錯誤樹從 0.35 升到 0.51，剛好超過 0.5 的門檻。所以「錯誤樹 > 0.5」的 run 數從 0 變成 1。
- **錯誤率高估時，模式 2 會回來。** 〔實測〕e0／real／sw5 用 e = 0.03（真實值 0–0.4%）：real s2 的錯誤樹 0.985，sw5 s1 0.92；e0 的 C1／C2 合併 0.82／0.47／1.00（eps 0.01 是 0.007／0.116／0.996）。原因和 composite weight 相同：e 越大，分支證據越弱，壓不過 prior。〔推論，見第 2.3 節的拆解〕
- **e 低估時，模式 1 只部分改善。** 〔實測〕b03 用 e = 0.004：segment C 相容比例 0.99／0.38／0.58，clone 數 3／4／5。
- **P2（直線樹）在所有 arm 都穩健。** 〔實測〕`c3_under_c4` ≤ 0.001。
- **建議：** 採用誤差模型，取代 eps 模型，**e 必須從 normal 樣本校正**，不要用保守的高估值。HCC1395BL 的校正值是 0.004（`2026-10-25_c4_robustness` 第 2 節）。real s1 的失敗原因要先查清楚，再判斷這是不是一個需要修的問題。

### 2.4 real s1 的根因（逐 SNV、逐 read）

暫存腳本比較 MAP 和最佳相容樹（C2+C4 合併、SNV 位置最佳化）。〔實測〕

- **pair term 的差（14.5）全部來自 2 個 SNV。** MAP 把 s6_04、s6_08 從 C3 分出來，放成 C3 上方的另一個 node。8 個 relation 不同的 pair 合計 +14.51；其他 SNV 的位置不影響 pair term。
- **s6_04 × s7_07（+6.94）：s7_07 的觀測 HP 判錯。**
  - s7_07 在真值裡位於 HP1，屬於 C3（CCF 0.10，VAF 約 2%）。
  - 帶突變的 read 只有 1 條，而且沒有 tag。被 tag 成 HP2 的 2 條 alt read，都是不帶突變的 read 發生 ref→alt 鹼基錯誤。
  - 多數決（HP1 0、HP2 2）把它判成 HP2，所以 s6_04 × s7_07 變成 HP2 上的合格 pair。s7_07 在 HP2 上其實沒有突變，於是 s6_04 的 alt read 看起來是「s6_04 有、s7_07 沒有」，支持 s6_04 是 s7_07 的祖先。
- **s6_08 的 6 個 pair（+7.1）：同一組錯誤 read 被重複計算。**
  - s6_08 有 4 條真的帶突變的 read，另有 2 條不帶突變的 read 被鹼基錯誤讀成 alt（期望 71 × 0.004 ≈ 0.28 條，P(≥ 2) ≈ 3%）。
  - 這 2 條 read 同時出現在 s6_08 與 s6_01、s6_03、s6_05 等 pair 的 01 計數裡。誤差模型把每個 pair 當成獨立證據，所以同一個錯誤被罰了好幾次。這是 `2026-10-25_c4_robustness` 第 8 節的 read 重複計算問題；誤差模型降低了每次的罰分，但沒有解決重複。
- **HP 判錯有多常見**（`c4_robustness` 的 27 個 sim）：
  - 鹼基錯誤造成：每個 sim 0–5 個 SNV，都在 C3 的 s6、s7（b01、b03、real s1）。
  - phase switch 造成：一次 9–49 個 SNV（sw1 s1、sw5、real s2），屬於模式 2 的已知來源。
- **簡單門檻不是好的修法。** 只在「該 HP 的 alt 數 ≥ 錯誤能解釋的數量」（binomial 尾端，α = 0.01）時才相信 snv_hp：假設錯誤率 0.004 時，判錯的 SNV 保留 22／26，判對的 SNV 誤刪 4.9%；假設 0.03 時，保留 9／26，誤刪 22.4%。低 VAF clone 的真 alt 和錯誤 alt 都只有個位數，門檻分不開它們。（26 個判錯的 SNV 中，real s2 那批主要來自 switch。）
- **含義：** 低 CCF 的 clone 正是 C4 最想解析的對象，但它們的 SNV 也最容易被判錯 HP。〔推論〕

- 資料：`2026-10-25_c4_robustness/sims/x10_{e0,real,sw5,b03}_s{1,2,3}`，沒有重生。這些 sim 已經通過 `2026-10-26_sim_expectation_check` 的全部檢查。

- 誤差模型：`tools/phyclone_pairs.py` 的 `error_relation_scores`（commit `5b77349`）。

L=lab_report/2026-10-26_c4_error_model

## 4. 限制

- 只有一棵手寫樹、×10 密度、一個 MCMC seed。
- 模型和模擬器的錯誤機制相同（逐位點、對稱、獨立）。真實 ONT 有位點相關的長尾，這裡沒有測到。〔推論〕這對誤差模型有利。
- 「校正組合」是從兩個 arm 挑出來組合的，不是另外跑的；每個 sim 只用了一個 e。
- 判定門檻（錯誤樹 > 0.5）仍是提案，未經老闆同意。real s1 的 0.513 剛好在門檻附近。
- A2＋誤差模型沒有跑。
