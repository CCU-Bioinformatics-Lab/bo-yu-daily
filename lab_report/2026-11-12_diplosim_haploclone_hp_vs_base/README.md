# diplosim SNV-only：haploclone 加 HP（A1）和不加 HP（base）有沒有差別（2026-11-12）

接續 `../2026-11-12_diplosim_haploclone_first_run/`（1 棵樹看不出差別）。本週主軸第 3 項。用到的會議：2026-11-11（附錄 C 第 3 項、O6）。標記：〔實測〕本實驗計算；〔程式〕讀程式；〔推論〕本檔推論。

**真值來源：** 模擬（diplosim）。**讀長：** 不適用，diplosim 直接產生計數。**輸入：** 一個 bulk sample 的 ref／alt 計數，含 HP1／HP2。**生成程式：** 本 repo `diplosim/`。

## 1. 結論

- **樹的關係：HP 沒有差別。** 樹關係正確率 A1 − base ＝ −0.011（95% CI −0.036 到 +0.013）。10 棵樹裡 A1 較高 5 棵、較低 5 棵。符合事先定的「沒差」標準（CI 包含 0，且絕對值 < 0.02）。〔實測〕
- **CCF：HP 讓估計稍微準一點。** CCF 誤差 A1 − base ＝ −0.0019（CI −0.0035 到 −0.0003），10 棵中 7 棵 A1 較準。但改善的絕對值很小（約 0.002）。〔實測〕
- **分群（ARI）：A1 有偏好的趨勢，但不顯著。** +0.023（CI −0.0015 到 +0.048），8 棵較高。〔實測〕
- **和預期一致。** 全部 1+1 時，A1 只用 SNV 所在 HP 的 read 估 CCF，所以 CCF 會稍準、分群可能稍好；但它不提供 SNV 之間的關係，樹形仍只靠 CCF 加總規則決定。〔程式〕`haploclone/rust/src/data/hp.rs`；〔推論〕
- **haploclone 本身：** 真值都是 5 群，重建出 3–5 群；樹關係正確率 0.85–0.99。兩個 seed 之間樹關係正確率平均差 0.023、最大 0.12，和 A1 與 base 的差同一個量級。〔實測〕

**能證明：** 在這組設定（5 clone、1,000 SNV、coverage 400、purity 0.7–0.9、全部 1+1、單一 sample），HP（A1）不會改善樹的關係，只讓 CCF 略準。**不能證明：** 其他設定下也一樣（較低深度、較多 clone、有拷貝數變化、有同 read 共現）；也不能證明 HP 對樹重建沒用，只表示這個情境下沒用。

## 2. 事先定好的比法

在批次開始前定好（對話紀錄，2026-11-12）：

- 10 棵模擬樹（diplosim seed 1–10），每棵 base 和 A1 各跑 2 個 haploclone seed。
- 每棵樹先把 2 個 seed 平均，再算 A1 − base；報告 10 棵樹的平均差和 t 95% CI。
- 主要指標是樹關係正確率。「沒差」＝ CI 包含 0 且絕對值 < 0.02。
- ARI、CCF 誤差、clone 數是次要指標，沒有事先定門檻；它們的結果只當描述。

## 6. 對下一步的意義〔推論〕

- 在 SNV-only、全部 1+1、單一 sample 的設定下，HP 對樹形沒有幫助。這是模型結構決定的，不是調參能改的。
- HP 要對樹重建有用，要有以下其中之一：拷貝數不同的區域（A2 emission），或同一條 read 上的共現（C4；diplosim 沒有 read）。選哪一條路是設計選擇，要先決定。

## 7. 複查與投影片用說法（2026-11-13）

**複查〔實測〕**
- 40 組（10 樹 × base／A1 × 2 seed）都有 MAP 輸出；log 沒有 error、panic、NaN。
- 用 `results.tsv` 重跑摘要腳本，和 `summary.txt` 完全相同；平均差與 t 95% CI 另外獨立重算，三個指標一致。
- 第 4、8、10 棵兩個 seed 的 MAP 樹相同。兩個 seed 的 log 不同，表示 seed 有生效，只是收斂到同一棵 MAP。

**措辭修正**
- 主要指標符合事先定的「沒差」規則，但 CI 下限 −0.036 超出 ±0.02，所以不算證明兩者等價。投影片寫「這組設定下沒看到 HP 改善樹形」，不寫「確認 HP 沒差」。要證明等價，需要更多樹，讓整條 CI 落在 ±0.02 內。
- haploclone 換 seed 的變異（樹關係正確率平均 0.023，最大 0.12）和 A1 − base 的差同一量級。

**為什麼沒差（投影片一句話）**
- 有些 clone 的 CCF 本來就很接近（真值，例如第 7 棵 0.42 和 0.49）或很小（第 10 棵 0.01），haploclone 分不開，所以 5 群只找回 3–5 群；base 和 A1 都一樣。〔實測〕
- HP 只讓每個 SNV 的 CCF 稍準（誤差少約 0.002），不足以分開這些群；全部 1+1 時，HP 也不提供 SNV 之間的關係，所以樹形沒有改善。〔程式〕`haploclone/rust/src/data/hp.rs`；〔推論〕
- 因果方向：CCF 接近是模擬真值本來的樣子，不是 HP 造成的。
- 不是 diplosim 模擬錯：SNV-only 是 11-11 週會確認的第一階段。也不是只怪 haploclone：分群弱點在 base 也一樣。主因是「全部 1+1 ＋ A1 只用 HP 估 CCF」這組設定。
- HP 要對樹形有用，需要拷貝數不同的區域（A2）或同 read 共現（C4）。選哪條是設計選擇，帶到週會。
