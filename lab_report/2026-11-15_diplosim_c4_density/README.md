# 模擬：SNV 密度要多高，共現才夠用（2026-11-15）

**狀態：** 20／50／100 完成，200 失敗（2026-11-16）。使用者 2026-11-15 決定「掃模擬的 SNV 密度，看看要多少對才夠」。接續 `../2026-11-15_diplosim_c4_center/`（中心點沒有改善，原因是 SNV 對太少）。

## 1. 設定（跑之前寫下）

- **只改一個參數：** `--snvs-per-mb` = 20、50、100、200（中心點 5.3 已跑過，直接沿用）。其他和中心點相同：`--n-clones 5 --n-snv 1000 --coverage 60 --purity 0.9 --read-length 33000`，diplosim seed 1–10，haploclone seed 1、2，`-b 1000 -n 3000 --num-chains 4`。
- 密度只改 SNV 位置，所以樹、CCF、read 計數和中心點完全相同（`diplosim/DECISIONS.md` 2026-11-15）；只有 SNV 對的數量變多。
- **預期每個 SNV 的同 HP 鄰居數** ≈ 密度 × read 長度 × ½（HP 相同）× 2（左右兩邊）= 密度 × 0.033：5.3 → 0.17、20 → 0.66、50 → 1.65、100 → 3.3、200 → 6.6。〔推論〕
- **模式：** `a1`（核對用，應和中心點相同）和 `a1c4pool`（A1＋共現＋共用比例）。中心點 `a1c4` 和 `a1c4pool` 找回群數相同，為了省時間只跑 `a1c4pool`。
- 指令（每個密度一次）：`python3 -I tools/run_diplosim_haploclone_batch.py /bip8_disk/boyu114/diplosim_c4_2026-11-15/d<密度> --sim-seeds 1-10 --hc-seeds 1,2 --coverage 60 --purity 0.9 --read-length 33000 --snvs-per-mb <密度> --modes a1,a1c4pool --jobs 24`（`run_density.sh`）。

## 2. 事先定的判定

- 評分和中心點相同（`../2026-11-15_diplosim_c4_center/summarize_c4.py`）：找回群數（80/80）、樹形完全對、依 CCF 差距分組的找回比例。
- **每個密度：** `a1c4pool` − `a1` 平均多 ≥ 0.3 群，而且 t 95% CI 不含 0，算「有改善」。
- **要回答的問題：** 最低哪個密度開始有改善；CCF 差 < 0.1 的群，在哪個密度開始超過只看計數的天花板（60× 加 HP：< 0.05 為 10%、0.05–0.1 為 0%）。同時記下每個密度 CCF 相近 clone 之間實際有幾對 SNV。
- **核對：** 每個密度的 `a1` 都應該是 1.95 群（和中心點相同）。

## 3. 限制

- 密度 20 以上比 HG008 實測（約每 Mb 5 個 SNV）密很多。這個實驗回答「需要多少 SNV 對」，不代表真實資料能達到。
- diplosim 沒有定序錯誤，結果偏樂觀。10 棵樹，CCF 差距只能事後分組。
