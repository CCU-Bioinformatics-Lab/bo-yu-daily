# haploclone 自己的評分：真值樹和它找到的 MAP 樹，哪個分數高（2026-11-16）

**狀態：** 完成（2026-11-16）。使用者 2026-11-16 決定「先做 2」。這是第 ② 步的第一個動作，只診斷，不改 haploclone 的行為。

## 1. 問題

`../2026-11-16_cooccurrence_oracle/` 顯示：每 Mb 100 個 SNV 時，上限 4.00 群，haploclone（A1＋共現＋共用比例）3.00 群。差距不是資訊不夠。這一步要分辨差距來自哪裡：

- **搜尋：** 真值樹的分數比較高，但 haploclone 沒走到；或
- **評分：** haploclone 的評分本身就給真值樹比較低的分數。

兩種原因的改法不同，所以先分辨，再決定第 ② 步改哪裡。

## 2. 做法與判定（跑之前寫下）

- 資料：`/bip8_disk/boyu114/diplosim_c4_2026-11-15/{center,d20,d50,d100}` 的 `a1c4pool`（10 棵樹 × 2 個 seed）。不重跑模擬或 haploclone。
- 新寫的小程式 `haploclone/rust/examples/score_tree.rs`：讀一棵指定的樹（每個 SNV 在哪個 node、node 的親子關係），用 haploclone 取樣時的目標分數 `TreeJointDistribution::log_p_one`（`haploclone/rust/src/joint.rs:57`）算分，並拆成 prior、read 計數、共現三部分。它是獨立的 example，不改主程式。
- `score_truth.py`：每次重建，算真值樹和 MAP 樹的分數。兩棵樹用同一個 alpha（MAP 那次 iteration 的 alpha）。
- **核對：** 重算的 MAP 分數要等於 trace 裡記的分數（差 < 1e-6）。
- **判定（每個密度 20 次重建）：**
  - 真值 − MAP > 0 佔多數 → 搜尋問題。第 ② 步改搜尋（例如一次移動一組 SNV）。
  - 真值 − MAP < 0 佔多數 → 評分問題。看是 prior、計數還是共現那一部分把真值壓低，第 ② 步改那一部分。
- 另外分開看「MAP 已經找回全部 5 群」和「沒找回」的重建。

## 3. 限制

- 真值樹不一定是分數最高的樹。真值 < MAP 只表示評分不偏好真值，不表示 MAP 是最佳解。
- 只比較兩棵樹，不知道兩者之間有沒有分數更高的樹。
- diplosim 沒有定序錯誤；10 棵樹。

## 4. 結果〔實測〕

`truth_vs_map_summary.txt`、`truth_vs_map.tsv`（每次重建一列）。

- **核對：** 重算的 MAP 分數和 trace 最大差 4.8e-5。比事先寫的 1e-6 大，但分數本身約 −2,500，下面的差距是幾十到幾百，不影響結論。原因可能是加總順序不同〔推論〕。

**真值樹 − MAP 樹（haploclone 自己的分數；正值表示真值比較高）**

| 每 Mb SNV | 真值分數較高 | 總分（中位數） | prior | read 計數 | 共現 |
|---|---|---|---|---|---|
| 5.3 | 0／20 | −155.2 | −212.7 | +23.2 | +4.0 |
| 20 | 0／20 | −96.7 | −154.8 | +12.5 | +14.0 |
| 50 | 0／20 | −46.9 | −54.0 | −3.3 | +4.1 |
| 100 | 2／20 | −29.7 | −31.3 | +3.6 | +4.2 |

- **80 次重建中 78 次，haploclone 的評分給真值樹比較低的分數。** 所以不是搜尋沒走到，是評分不偏好真值。
- **把真值壓低的是 prior。** prior 這一項在 80 次中 78 次不利於真值（中位數 −31 到 −213）。
- **資料這一邊多半支持真值。** 只看 read 計數加共現（跑完後補算，不在 §2）：真值較高的有 15／20、14／20、11／20、13／20（密度 5.3 到 100）。但幅度只有幾到幾十，蓋不過 prior。
- **密度 100、MAP 已找回 5 群的 3 次：** 真值 − MAP 是 −6.5、−6.9、−14.3，prior 幾乎沒差（+1.2、+0.5、−3.5）。兩棵樹很接近，差在少數 SNV 的分配。

**prior 為什麼不利於真值〔程式〕〔推論〕**

- prior 的分群項是 K × ln α ＋ Σ ln((n − 1)!)，n 是每個 node 的 SNV 數（`haploclone/rust/src/prior.rs:224-232`，沿用 PhyClone 的 CRP）。
- 這一項偏好「一大群加幾個小群」。例：兩群各 200 個 SNV，合併成 399＋1 時，這一項多 273（lnΓ(399) − 2 × lnΓ(200)）。
- 例子（密度 100、第 9 棵樹、seed 1）：真值 5 群是 500／84／207／92／117 個 SNV。MAP 只有 4 群 533／258／86／123，把 CCF 0.89 和 0.81 的兩群併成一群（CCF 0.82）。真值的 prior 比 MAP 低 202；計數（+8.9）和共現（+49.3）都支持真值，仍不夠。

## 5. 照 §2 判定

**評分問題，不是搜尋問題；壓低真值的是 prior 的分群項。** 原先設想的「共現當錨點、一次移動一組 SNV」是改搜尋，照這個結果幫不上：就算走到真值樹，分數也比較低，haploclone 會走回去。

## 6. 能證明／不能證明

**能證明：**
- 在這 4 組密度、80 次重建中，haploclone 現行評分（A1＋共現＋共用比例、預設 prior）不偏好真值樹。
- 原因在 prior，不在 read 計數或共現那兩項。

**不能證明：**
- 換 prior 之後就能找回 CCF 相近的群。只看計數加共現時，真值也只在 11–15／20 次勝出，幅度不大；而且換 prior 可能讓它在別的地方多分出假的群。
- 搜尋完全沒問題。評分偏向錯的樹時，看不出搜尋好不好。
- 只看計數（不加共現）的 A1、base 也一樣。這次只算了 `a1c4pool`。

## 7. 下一步（設計選擇，還沒決定）

haploclone 已有三個 prior 的研究選項，預設都關閉（`haploclone/rust/src/main.rs` 的 `--prior`、`--prior-tau`）：

| 方案 | 做法 | 優點 | 風險 |
|---|---|---|---|
| 甲：`--prior-tau` < 1 | 把分群項乘上小於 1 的係數 | 改動最小，可以掃一個數字 | 係數沒有理論依據，容易變成調參 |
| 乙：`--prior uniform-partition` | 拿掉 Σ ln((n − 1)!)，只留群數的懲罰 | 沒有要調的數字；不再偏好大群 | 可能多分出小群 |
| 丙：`--prior pitman-yor` | 換成 Pitman–Yor，多一個 discount 參數 | 有文獻依據的推廣 | 多一個參數；仍偏好大群，只是較弱 |

便宜的第一步：用同一支 `score_tree` 的方法，在這三種 prior 下重算「真值 − MAP」，不必重跑 haploclone。它能先排除沒用的 prior。

## 8. 三種 prior 下重算（使用者 2026-11-16 決定；規則在算之前寫下）

**問題：** 換成哪一種 prior，haploclone 的評分才會偏好真值樹？

**做法**
- 不重跑 haploclone。`score_tree` 多一個參數，在同一棵樹上算各種 prior 的值；read 計數和共現兩項不變。腳本 `score_priors.py`。
- prior：現行 CRP（`crp:1`，核對用）；`--prior-tau` 0.5、0.2、0.05；`uniform-partition`；Pitman–Yor discount 0.25、0.5、0.75。alpha 同 §2（MAP 那次 iteration 的值，三棵樹共用）。
- 每次重建比三棵樹：
  1. **真值樹。**
  2. **MAP 樹：** haploclone 在現行 prior 下找到的樹。
  3. **多分樹（對照）：** 真值樹裡最大的非主幹群，照 SNV 的 VAF 排序從中間切開；VAF 高的一半留在原 node，低的一半放進新 node，接在原 node 下面，原本的子群改接新 node。這一群其實只有一個 CCF，切開是假的。照 VAF 切會讓 read 計數那一項變好，所以它測的是 prior 擋不擋得住假分群。

**判定（每個密度 20 次重建，每種 prior）**
- 真值 > MAP 而且真值 > 多分樹，才算這次「偏好真值」。
- 一種 prior 在某個密度有 ≥ 15／20 次偏好真值，算「可用」，值得真的跑 haploclone。
- 真值 > MAP 多、真值 > 多分樹少 → 這個 prior 太鬆，會分出假群。反過來 → 太緊，會併群。

**限制**
- MAP 樹是在現行 prior 下找到的。換 prior 後 haploclone 會找到別的樹，所以「可用」只是必要條件，不保證重建變好。
- 多分樹只是一種假分群；別種假分群（例如切成三群、切別的群）沒有測。
- 「偏好真值」比兩棵對照樹嚴格，但真值仍不一定是分數最高的樹。

### 8.2 判定與意義

- **照 §8 的規則：三種 prior 都不可用。** 不值得用它們重跑 haploclone。
- **問題不在 prior 選錯，在評分分不出真分群和假分群〔推論〕。** prior 要夠強才能擋住假分群；夠強時，就一併擋住真的相近的群。
- **共現目前沒有幫忙擋假分群〔推論〕。** 把一群切成兩半時，兩半之間的 SNV 對只會有 11 和 00 的 read。現行共現評分把「只帶祖先突變的 read 比例」當成自由的數字（`haploclone/rust/src/pairs.rs:287-296` 的 Beta），比例是 0 也幾乎不扣分。它沒有檢查這個比例和兩個 node 的 CCF 差對不對得上。這一項我沒有另外輸出數字，是從 uniform 下的差距（約 −60，和只看計數的估計相同）推出來的。

**能證明：** 在這 80 次重建、這三棵樹的比較下，換 prior（tau、uniform、Pitman–Yor）不能同時做到「偏好真值、不偏好假分群」。

**不能證明：**
- 所有 prior 都不行。只測了 haploclone 已有的三類、8 個設定。
- 多分樹以外的假分群也一樣。
- 改共現評分（把比例綁到 CCF 差）就能解決。這是下一個假設，還沒有測。

## 9. 方案甲的離線重算：共現比例綁到 CCF 差（使用者 2026-11-16 決定；規則在算之前寫下）

**問題：** 把共現評分改成「read 比例要對得上 CCF 差」之後，評分會不會偏好真值、同時擋住假分群？

**做法**
- 不改 haploclone、不重跑。腳本 `score_ccf_tied.py`，三棵樹和 §8 相同（真值、MAP、多分樹）。
- 每個 node 的 CCF：用該 node 全部 SNV 在自己 HP 上的 read 計數估計（alt 總數 ÷（read 總數 × purity），最大 1）。三棵樹用同一個估法，不用真值 CCF。
- 新的共現分數只改一處。現行評分對兩個 node 之間的 SNV 對，把比例當成自由的數字（Beta 積分，`haploclone/rust/src/pairs.rs:287-296`）。新評分把比例固定成 CCF 算出來的值 ρ：
  - 祖先 a 在子代 b 上面：帶突變的 read 中，「只帶 a」的比例 ρ ＝（CCF_a − CCF_b）÷ CCF_a。
  - 兄弟：「只帶 a」的比例 ρ ＝ CCF_a ÷（CCF_a ＋ CCF_b）。
  - ρ 限制在 [0.01, 0.99]。同一個 node 內的 SNV 對、不該出現的 read（eps 0.01）都和現行相同。00 read 不計分，和現行相同。
- read 計數那一項和 prior 用 `score_tree` 的值；8 個 prior 設定同 §8。
- **核對：** 腳本用同一套程式重算現行的共現分數，要和 `score_tree` 輸出的共現分數相同（差 < 1e-3）。

**判定：** 和 §8 相同。真值 > MAP 而且真值 > 多分樹算「偏好真值」；某個 prior 在某個密度 ≥ 15／20 次算「可用」。另外列出共現那一項單獨的差（真值 − 多分樹），核對 §8.2 的推論。

**限制**
- node 的 CCF 是直接代入的估計值；haploclone 實際上把 CCF 積分掉。真的實作時數字會不同。
- 其他同 §8（MAP 是現行評分找到的；只有一種假分群；沒有定序錯誤）。

### 9.2 能證明／不能證明

**能證明：**
- 現行共現評分擋不住假分群；把比例綁到 CCF 差之後擋得住，條件是每 Mb 約 50 個 SNV 以上。
- 即使綁定 CCF、放鬆 prior，在密度 100 也只有 13／20 次偏好真值，沒過事先定的門檻。
- 密度 5.3 和 20 幾乎沒有改善。

**不能證明：**
- 真的實作後 haploclone 的重建結果。這裡用代入的 CCF 估計值，而且 MAP 是現行評分找到的。
- 13／20 和門檻 15／20 的差距有意義。只有 10 棵樹 × 2 個 seed，同一棵樹的 2 個 seed 不獨立。
- 真實資料的表現。沒有定序錯誤；密度 50–100 約是 HG008 的 10–19 倍。

### 9.3 對方案的意義

- **方案甲（綁定 CCF）：** 有效果但不夠，而且只在真實資料達不到的密度有效。照事先的規則，不值得現在實作。
- **到目前為止的三個結果指向同一件事：** 在 HG008 等級的密度、60×、單一 sample、1+1 下，CCF 差 < 0.1 的群分不開，原因是資訊不夠（`../2026-11-16_cooccurrence_oracle/`：上限等於只看計數），換 prior（§8）或改共現評分（§9）都救不回來。
- 剩下的選擇是方案乙（完成標準改成群層級）或方案丙（寫成限制）；這是研究目標的選擇，帶週會。
