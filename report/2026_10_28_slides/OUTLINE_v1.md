## 貫穿全冊的真實例子

全部取自 PhyClone 作者公開的 benchmark 資料，不是自己編的。

- 資料：`FS-CRP_Loss/loss_prop_0.0_run0`（PhyClone 作者用這套程式產生；參數和程式介面完全對得上）。
- 規模：600 個 SNV、8 個 sample、每個位點深度 1000、purity 1.0、總拷貝數 2–6。
- 樹：9 個 clone。root 有 291 個 SNV。root 下有 6 個 child（125、73、55、17、15、13 個 SNV）。17 那群往下接 10 那群，再往下接 1 那群。
- 追蹤的 SNV：`m392`。它是最小那群（1 個 SNV）唯一的 SNV，位在 chr19。
- `m392` 在 sample s0：CCF 0.061；總拷貝數 4（3＋1）；突變在拷貝數改變之後，所以 4 份裡只有 1 份帶突變；期望突變 read 比例 0.0161；抽到突變 read 17 條、正常 read 983 條。
- `m392` 在 sample s3：拷貝數變成 5（4＋1），突變在拷貝數改變之前，5 份裡有 4 份帶突變。

（`m392` s0 的期望比例已用程式公式手算核對：(1−0.061)×0.001＋0.061×1/4＝0.0161，和資料檔的值相同。）

- 標題：「PhyClone 的模擬資料怎麼產生？」
- 副標：逐步對照程式原碼。

### P2 標題：「上次的三個問題，這次的三個答案」
- 圖：三列「問題 → 答案」卡。
  1. 模擬資料怎麼產生？→ 五步：分群 → 接成樹 → 每個 clone 的比例 → 拷貝數 → 抽 read 數。

  3. 能不能直接用？→ 不能。前三步可以沿用，後兩步要重寫。
- 頁面文字：同上三個答案。
- 講稿：先說這次的結論，全部來自直接讀程式原碼，不是 AI 的轉述。程式是 PhyClone 公開 repo 裡的模擬程式。橋接：「判斷能不能用之前，先列出我們要什麼」。

### P3 標題：「我們要的模擬資料要有五樣東西」
- 圖：需求清單，五張小卡，各配一個小圖示。
  1. long read：一條 read 長到能跨過多個位點。
  2. 真值樹：知道答案。
  3. HP：每條 read 知道來自哪一份同源染色體。
  4. 同 read 共現：一條 read 上同時看到兩個突變。
  5. 拷貝數跟著 clone 走：同一個 clone 在不同 sample 的拷貝數一致。
- 頁面文字：我們只用 long read 模擬資料。short read 資料集都不用。
- 講稿：第 5 條是生物假設：拷貝數改變是發生在某個 clone 的事件，會遺傳給後代。這張清單在第 12 頁逐條對照。橋接：「接下來照程式執行順序，一步一步看 PhyClone 怎麼產生資料」。

## 第一大段：程式怎麼產生資料（eyebrow：1 · 程式怎麼產生資料）

### P4 標題：「PhyClone 的模擬分五步，前三步產生樹，後兩步產生 read 數」
- 圖：五格橫向流程，每格寫「輸入 → 做什麼 → 輸出」。前三格一色（樹），後兩格另一色（read 數）。
  1. 分群：600 個 SNV → 分成幾群。
  2. 接成樹：幾群 → 一棵樹。
  3. clone 比例：樹 → 每個 sample 中每個 clone 的比例。
  4. 拷貝數：每個 SNV、每個 sample → 拷貝數與帶突變的份數。
  5. 抽 read 數：以上全部 → 正常 read 數、突變 read 數。
- 流程下方一條小字：真實例子：作者 benchmark 的一份資料，600 個 SNV、8 個 sample、深度 1000。
- 講稿：前三步在一個程式檔，後兩步在另一個。我們用作者公開資料中的一份貫穿全冊，追蹤一個 SNV，叫 m392。

### P5 標題：「第一步：600 個 SNV 依中國餐廳過程分成 9 群」
- 圖左：中國餐廳過程示意。突變一個一個入座；選舊桌的機率和桌上人數成正比；另有一個固定機率開新桌。
- 圖右：真實結果。9 個長條，長度是每群 SNV 數：291、125、73、55、17、15、13、10、1。最短那條標「m392 在這群」。
- 頁面文字：大群越來越大，所以群的大小很不平均。
- 講稿：開新桌的機率由一個參數決定。程式預設值是 1；作者 benchmark 用的值沒有公開。結果大群很大、小群很小。

### P6 標題：「第二步：群由小到大接成樹，最大的群一定是 root」
- 圖左：建樹規則三格動畫式示意（示意，非真實）。
  1. 群依大小由小到大排隊。
  2. 每加入一群，就從目前「還沒有 parent」的群裡隨機收 0 個到全部當 child。
  3. 最後一群（最大）收下剩下所有沒有 parent 的群。
- 圖右：真實樹。root 291 → 125、73、55、17、15、13；17 → 10 → 1（m392）。
- 頁面文字：parent 一定比 child 晚加入，所以 parent 一定比 child 大。作者 100 棵樹全部符合。
- 講稿：作者的 100 棵樹，root 都是最大群；741 條邊都是 parent 的 SNV 數不少於 child。這是程式造成的偏向，下一段會和論文寫法比較。

### P7 標題：「第三步：每個 sample 隨機分配 clone 比例，CCF 是自己加上所有後代」
- 圖左：sample s0 的比例條。9 個 clone 的比例加起來是 1（隨機打散，每個 sample 各抽一次）。
- 圖右：真實樹上 17 → 10 → 1 這條鏈，標 s0 的兩個數字：
  - 1 那群：自己 0.061，CCF 0.061。
  - 10 那群：自己 0.065，CCF 0.125（＝0.0646＋0.0607）。
  - 17 那群：自己 0.050，CCF 0.175（＝0.0496＋0.1252）。
  - root：CCF 1。
- 頁面文字：CCF 是自己的比例加上所有後代的比例。root 的 CCF 一定是 1。
- 講稿：每個 sample 分開抽，所以同一個 clone 在 8 個 sample 中比例不同。m392 在 s0 的 CCF 是 0.061，等一下會用到。

### P8 標題：「第四步：每個 SNV 在每個 sample 重抽一次拷貝數」
- 圖：m392 在兩個 sample 的染色體示意。
  - s0：總拷貝數 4（3＋1）。突變在拷貝數改變之後 → 4 份裡只有 1 份帶突變。
  - s3：總拷貝數 5（4＋1）。突變在拷貝數改變之前 → 較多那邊的 4 份都帶突變。
- 圖下：規則三格：總拷貝數在 2–6 之間均勻抽 → 拆成較多／較少兩邊 → 擲硬幣決定突變在拷貝數改變之前或之後。
- 頁面文字：同一個突變，在不同 sample 的拷貝數不同。
- 講稿：真實腫瘤中，同一個 clone 的拷貝數不會因為取樣位置不同就改變。這是程式的簡化，不符合 P3 第 5 條。作者這份資料的 600 個 SNV，全部在 8 個 sample 中出現至少 2 種拷貝數組合。

### P9 標題：「第五步：依三群細胞算出突變 read 比例，再抽 1000 條 read」
- 圖：一個位點的細胞組成長條，分三段：正常細胞（purity 1，所以 0）、沒帶突變的腫瘤細胞（1−0.061）、帶突變的腫瘤細胞（0.061）。每段下方畫它的染色體份數與突變份數。
- 圖右：計算：突變 read 比例＝0.939×0.001（定序錯誤）＋0.061×1/4＝0.0161 → 抽 1000 條 → 突變 17 條、正常 983 條。
- 頁面文字：每個位點各自抽 read 數。程式不產生 read 本身。
- 講稿：0.001 是定序錯誤率。抽法是二項分布：像擲 1000 次不公平的硬幣。程式算出的 0.0161 和資料檔記錄的值相同，我們手算核對過。重點是：每個位點分開抽，所以位點之間沒有「同一條 read」的關係。

### P10 標題：「輸出是一張 read 數表和一棵答案樹，沒有位置也沒有 HP」
- 圖左：輸出表一列（m392、s0）：突變 read 17、正常 read 983、拷貝數 3＋1、purity 1.0。旁邊列「沒有的欄位」：真實基因組位置（只有序號 392）、read 序列、HP。
- 圖右：答案檔：樹、每群有哪些 SNV、每個 sample 的 CCF。
- 頁面文字：方法只看到 read 數表。答案檔在評分時才用。
- 講稿：作者的輸入檔其實也帶了答案欄位，但 PhyClone 不會讀。我們自己做時，輸入檔要拿掉答案欄。橋接：「流程看完了，接下來看它能不能直接拿來用」。

## 第二大段：能不能直接用（eyebrow：2 · 能不能直接用）

### P11 標題：「論文寫的和程式做的有兩處不同，而且部分程式沒有公開」
- 圖：左右對照，左「論文寫的」、右「程式做的」，同一列一件事。
  1. 樹形：所有樹形機率相同 ↔ 最大群一定是 root。
  2. 拷貝數：論文沒寫怎麼抽 ↔ 每個 SNV、每個 sample 重抽。
- 圖下：沒有公開的程式（斜線底）：突變丟失、另一種樹生成法、拷貝數擾動、寫成輸入檔。
- 頁面文字：用作者的模擬，會偏向「最大群在 root」的樹。
- 講稿：樹形偏向可能讓方法在判斷 root 時看起來比較準，這是我們的推論。沒有公開的程式代表作者 benchmark 的部分資料我們無法重做。

### P12 標題：「對照我們的五項需求，PhyClone 模擬只有真值樹」
- 圖：需求表（P3 的五項）× 「PhyClone 模擬器」一欄，只寫「有／無」，再加一欄「原因」短語。
  | 需求 | PhyClone 模擬器 | 原因 |
  |---|---|---|
  | long read | 無 | 不產生 read |
  | 真值樹 | 有 | 樹與 CCF 都存下來 |
  | HP | 無 | 拷貝數不分哪一份染色體 |
  | 同 read 共現 | 無 | 每個位點各自抽 |
  | 拷貝數跟著 clone 走 | 無 | 每個 SNV、每個 sample 重抽 |
- 頁面文字：五項只有一項符合。不能直接用。
- 講稿：每個「無」我們都在程式原碼中找到原因，位置記在 BRIEF。橋接：「不能直接用，但哪些部分可以留下來？」

### P13 標題：「前三步可以沿用，後兩步要重寫」
- 圖：P4 的五格流程重畫一次。前三格標「沿用」（第二步加註「修正偏向，或兩種都做」），後兩格標「重寫」，下面列重寫內容：
  - 第四步：拷貝數改成一段一段的區間，綁在樹的某條邊上，並指定在哪一份染色體（HP）。
  - 第五步：read 數拆成每份染色體；一條 read 跨多個位點；加入 HP 標錯與標不出來的情況。
- 頁面文字：目前進度：流程已設計，程式尚未實作。
- 講稿：沿用前三步的好處是樹與答案檔格式和作者一致，評分程式可以共用。第二步的偏向要請老師決定。
