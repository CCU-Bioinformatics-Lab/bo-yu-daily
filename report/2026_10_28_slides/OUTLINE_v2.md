## 主問題

PhyClone 的模擬資料是怎麼一步步產生的？能不能直接拿來做 long read 驗證？

- 對照使用者原話：「製作正確清楚，對觀眾好理解的 phyclone 模擬資料生成流程的報告」。
- 對照上次會議（2026-10-21）老師的問題：「說明模擬資料如何產生」「既有模擬有沒有考慮 HP1／HP2」「程式存在不代表可以直接用」。
- 第一大段回答：怎麼產生？（照程式執行順序）
- 第二大段回答：能不能直接用？不能的話怎麼做？（對照研究需求，先列路徑再收斂）

## 貫穿全冊的真實例子

全部取自 PhyClone 作者公開的 benchmark 資料。數值都已對過資料檔（兩位審查者與本人各核對一次）。

- 資料：`FS-CRP_Loss/loss_prop_0.0_run0`。`loss_prop_0.0` 表示沒有丟失突變的版本。
- 這份資料是不是用這套程式產生？〔推論〕證據有兩項：
  1. 資料檔的欄位名稱和程式的內部變數相同。
  2. 作者 100 棵樹的形狀，全部符合程式造成的偏向（見 P6）。
- 規模：600 個 SNV、8 個 sample、每個位點深度 1000、purity 1.0。
- 樹：9 個 clone。root 有 291 個 SNV。root 下有 6 個 child（125、73、55、17、15、13）。17 那群往下接 10 那群，再往下接 1 那群。
- 追蹤的 SNV：`m392`。它是 1 那群唯一的 SNV。選它的原因：它在最深的位置，可以一路看到 CCF 怎麼累加。
- `m392` 在 s0：
  - CCF 0.0607。
  - 拷貝數 3＋1。突變在拷貝數改變之後：沒帶突變的腫瘤細胞 4 份，帶突變的腫瘤細胞 4 份裡有 1 份帶突變。
  - 期望的帶突變 read 比例 0.0161。抽到帶突變 read 17 條、沒帶突變 read 983 條。
- `m392` 在 s3：
  - CCF 0.0394。
  - 拷貝數 4＋1。突變在拷貝數改變之前：沒帶突變的腫瘤細胞仍是 2 份，帶突變的腫瘤細胞 5 份裡有 4 份帶突變。
  - 期望比例 0.0753。抽到帶突變 read 68 條。
- 公式核對：s0、s3 都用程式公式（`sim_data_on_tree.py` L121–L146）手算，結果和資料檔記錄的值相同。

## 第一大段：程式怎麼產生資料（eyebrow：1 · 程式怎麼產生資料）

### P4 標題：「PhyClone 的模擬分五步，前三步產生樹，後兩步產生 read 數」
- 圖頂一行（第一句先講清楚例子資料的身分）：「例子：作者 benchmark 的一份模擬資料。只有 read 數，沒有 read。只拿來拆解流程，不當驗證資料。」
- 圖：五格橫向流程，每格三行：輸入 → 做什麼 → 輸出，下面再加一行「假設」。前三格一色（樹），後兩格另一色（read 數）。
  1. 分群：600 個 SNV → 9 群。假設：大群越容易變大。
  2. 接成樹：9 群 → 一棵樹。假設：群依大小加入。
  3. clone 比例：樹 → 每個 sample 每個 clone 的比例。假設：每個 sample 各自隨機。
  4. 拷貝數：每個 SNV、每個 sample → 拷貝數與帶突變份數。假設：每個 sample 各自重抽。
  5. 抽 read 數：以上全部 → 每個位點的 read 數。假設：位點之間各自獨立。
- 講稿：
  - 前三步在一個程式檔，後兩步在另一個。
  - 我們用作者的一份資料貫穿全冊，追蹤一個 SNV，叫 m392。
  - 這份資料是不是用這套程式產生？這是推論。證據是欄位名稱相同，而且樹形全部符合程式的偏向。
  - 把結果寫成檔案的程式沒有公開（搜尋範圍見判準）。

### P5 標題：「第一步：600 個 SNV 依中國餐廳過程分成 9 群」
- 圖左：中國餐廳過程示意。突變一個一個入座：
  - 選舊桌的機率和桌上人數成正比。
  - 開新桌的機率是 α ÷（已入座數＋α），越後面越小。
- 圖右：真實結果。9 個長條，長度是每群 SNV 數：291、125、73、55、17、15、13、10、1。最短那條標「m392 在這群」。
- 頁面文字：大群越來越大，所以群的大小很不平均。
- 講稿：α 控制開新桌的傾向。程式預設是 1；作者 benchmark 用的值沒有公開。

### P6 標題：「第二步：群由小到大接成樹，所以 parent 不會比 child 小」
- 圖左：建樹規則三格（示意，非真實）。
  1. 群依大小由小到大排隊。
  2. 每加入一群，就從目前「還沒有 parent」的群裡，隨機收 0 個到全部當 child。
  3. 最後一群（最大）收下剩下所有沒有 parent 的群。
- 圖右：真實樹。root 291 → 125、73、55、17、15、13；17 → 10 → 1（m392）。
- 頁面文字：parent 比 child 晚加入，所以 parent 的 SNV 數不小於 child。作者 100 棵樹的 root 都是最大群。
- 講稿：
  - 作者 100 棵樹的 741 條邊全部是 parent 不小於 child，其中 66 條兩邊一樣大。
  - 所以偏向不只在 root，每一條邊都有。
  - 下一段會和論文寫法比較。

### P7 標題：「第三步：每個 sample 隨機分配 clone 比例，CCF 是自己加上所有後代」
- 圖左：sample s0 的比例條。9 個 clone 的比例加起來是 1。
- 圖右：真實樹上 17 → 10 → 1 這條鏈，標出 s0 的兩個數字：
  - 1 那群：自己 0.061，CCF 0.061。
  - 10 那群：自己 0.065，CCF 0.125（＝0.0646＋0.0607）。
  - 17 那群：自己 0.050，CCF 0.175（＝0.0496＋0.1252）。
  - root：CCF 1。
- 頁面文字：CCF 是自己的比例加上所有後代的比例。root 的 CCF 一定是 1。
- 講稿：每個 sample 分開抽，各個 clone 機會均等。所以同一個 clone 在 8 個 sample 中比例不同。m392 在 s0 的 CCF 是 0.061，等一下會用到。

### P8 標題：「第四步：每個 SNV 在每個 sample 重抽拷貝數與突變時機」
- 圖上：規則四格。
  1. 抽總拷貝數。作者資料是 2–6。
  2. 拆成較多與較少兩邊，較少那邊至少 1 份。
  3. 抽時機：突變在拷貝數改變之前，或之後。
  4. 決定帶突變的份數：
     - 之後：只有 1 份。
     - 之前：較多那邊或較少那邊，二選一。
- 圖下：m392 在兩個 sample 的細胞示意。每個細胞畫出染色體份數，帶突變的份數標紅。
  - s0：3＋1、之後。沒帶突變的腫瘤細胞 4 份。帶突變的細胞 4 份，其中 1 份有突變。
  - s3：4＋1、之前。沒帶突變的腫瘤細胞 2 份。帶突變的細胞 5 份，其中 4 份有突變。
- 頁面文字：同一個突變，在不同 sample 的拷貝數不同。
- 講稿：
  - 「之前」時，沒帶突變的腫瘤細胞仍是 2 份。意思是拷貝數改變只發生在帶突變的細胞。
  - 總拷貝數是 2 時，兩種時機看起來一樣。
  - 真實腫瘤中，同一個 clone 的拷貝數不會因為取樣位置不同就改變。這是程式的簡化，不符合需求第 5 條。
  - 作者這份資料的 600 個 SNV，全部在 8 個 sample 中出現至少 2 種拷貝數組合。
  - 2–6 與「至少 1 份」是從作者資料反推的（程式預設是 1–6、至少 0 份）。所以作者資料沒有一邊完全消失的情況，也就是沒有 LOH。

### P9 標題：「第五步：依三群細胞的染色體份數算出突變 read 比例，再抽 1000 條 read」
- 圖左：m392 在 s0 的細胞組成長條，分三段：
  - 正常細胞：0（purity 1）。
  - 沒帶突變的腫瘤細胞：0.939。
  - 帶突變的腫瘤細胞：0.061。
  每段下方畫出它的染色體份數與帶突變份數（沿用 P8 的圖示）。
- 圖右：計算兩行：
  - 帶突變 read 比例＝帶突變的染色體份數 ÷ 全部染色體份數（每群依細胞比例加權）＋定序錯誤。
  - s0：0.0161 → 抽 1000 條 → 帶突變 17 條、沒帶突變 983 條。
- 頁面文字：每個位點各自抽 read 數。程式不產生 read 本身。
- 講稿：
  - 份數要加權。s0 剛好兩群腫瘤細胞都是 4 份，所以看起來像直接相乘。
  - s3 的兩群份數不同（2 份與 5 份），加權後是 0.0753，抽到 68 條。不加權會算成 0.0325，是錯的。
  - 0.001 是定序錯誤率。抽法是二項分布，像擲 1000 次不公平的硬幣。
  - 我們手算的 s0、s3 都和資料檔相同。
  - 重點：每個位點分開抽，所以位點之間沒有「同一條 read」的關係。
  - purity 1.0 不合實際；真實腫瘤樣本都混有正常細胞。

### P10 標題：「輸出是一張 read 數表和一棵答案樹，沒有位置也沒有 HP」
- 圖左：方法的輸入（m392、s0 一列）：帶突變 read 17、沒帶突變 read 983、拷貝數 3＋1、purity 1.0。旁邊列「沒有的資訊」：真實基因組位置（只有序號 392）、read 序列、HP。
- 圖右：答案檔：樹、每群有哪些 SNV、每個 sample 的 CCF。
- 頁面文字：方法只看到 read 數與拷貝數。答案檔在評分時才用。
- 講稿：
  - 公開的程式不寫檔，只把結果存在記憶體裡的樹上。作者的檔案由沒有公開的程式產生。
  - 染色體欄的 chr19 是合成的標籤，不是真實位置。
  - 作者的輸入檔也帶了答案欄位，但 PhyClone 不會讀。我們自己做時，輸入檔要拿掉答案欄。
  - 橋接：「流程看完了，接下來看它能不能直接拿來用」。

## 第二大段：能不能直接用（eyebrow：2 · 能不能直接用）

### P11 標題：「論文寫的和程式做的有四處不同，而且部分程式沒有公開」
- 圖：左右對照，左「論文寫的」、右「程式做的」，同一列一件事。
  1. 樹形：所有樹形機率相同 ↔ parent 不小於 child，root 是最大群。
  2. 樹根：多棵樹接到一個空的共同 root ↔ 一棵樹，root 本身帶突變。
  3. 拷貝數：論文沒寫怎麼抽 ↔ 每個 SNV、每個 sample 重抽。
  4. 帶突變份數與 read 抽法：建樹時允許 1 到較多那邊的份數，read 數分布較寬 ↔ 模擬只取 1、較多或較少那邊的份數，read 數用二項分布抽。
- 圖下：沒有公開的程式（斜線底）：突變丟失、另一種樹生成法、拷貝數擾動、寫成檔案。
- 頁面文字：用作者的模擬，會偏向「大群在上面」的樹。
- 講稿：
  - 樹形偏向可能讓方法在判斷祖先關係時看起來比較準。這是我們的推論。
  - 第 4 列的意思：生成的資料比建樹模型假設的更單純。
  - 「沒有公開」的範圍：PhyClone repo、論文補充文件、作者 benchmark 的資料目錄。
  - 沒有公開代表作者 benchmark 的部分資料我們無法重做。

### P12 標題：「對照我們的五項需求，PhyClone 模擬只有真值樹」
- 圖：需求表（P3 的五項）× 「PhyClone 模擬器」一欄，只寫「有／無」，再加一欄「原因」短語。
  | 需求 | PhyClone 模擬器 | 原因 |
  |---|---|---|
  | long read | 無 | 不產生 read |
  | 真值樹 | 有 | 樹與 CCF 都存下來 |
  | HP | 無 | 沒有父母來源不同的位點；較多／較少那邊每個位點各自決定，不對應固定的一份染色體 |
  | 同 read 共現 | 無 | 每個位點各自抽；也沒有真實位置 |
  | 拷貝數跟著 clone 走 | 無 | 每個 SNV、每個 sample 重抽 |
- 頁面文字：五項只有一項符合。不能直接用。
- 講稿：
  - 每個「無」都在程式原碼找到原因，位置記在 BRIEF。
  - 老師可能問：P8 不是已經分了較多和較少兩邊嗎？答：分了，但每個位點、每個 sample 各自重分。所以兩個位點的「較多那邊」不一定是同一份染色體。
  - 橋接：「不能直接用，有哪幾條路可以走？」

### P13 標題：「做 long read 模擬資料有三條路，我們先走自己寫生成器」
- 圖：三張卡並排，每張寫「做法／有什麼／缺什麼」。
  - A 只用現成的 long read 模擬器：有 read；缺 clone 樹與突變。
  - B 在真實 ONT read 上植入突變（建樹競賽的做法）：最接近真實；要先有樹、拷貝數、HP 的設計。
  - C 自己寫計數層生成器：快、可控制；沒有 read 序列。
- 圖下箭頭：先做 C → C 的設計直接當 B 的藍圖。
- 頁面文字：A 不能單獨用。先做 C，再用 C 的設計做 B。
- 講稿：A 只能提供 read，答案還是要我們自己設計。B 最像真資料，但植入前一樣需要 C 的那套設計。所以 C 是共同的第一步。

### P14 標題：「分群與 clone 比例沿用，拷貝數與抽 read 重寫，另外新增一步」
- 圖：流程重畫成六格，標「沿用」「修改」「重寫」「新增」。
  - 新增：放位置與父母來源不同的位點（劃出可接起來的區間）。
  - 分群：沿用。
  - 接成樹：修改。修正偏向（或兩種都做）；在樹的邊上放拷貝數事件。
  - clone 比例：沿用。
  - 拷貝數：重寫。改成一段一段的區間，指定在哪一份染色體。突變與拷貝數的先後由樹上的位置決定，不再隨機抽。
