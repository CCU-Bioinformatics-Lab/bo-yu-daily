# 報告與投影片規則

本檔是製作與修改投影片報告的規則。讀者是負責做簡報的 agent 與 subagent。報告對象是指導老師與實驗室成員；老師會追問主問題有沒有對準、證據從哪裡來。所以邏輯先過關，再做頁面。

2026-11-09 收斂：原本 76 條（多條只為某一頁而寫）合併成通用原則。舊代號對照見檔尾；舊條文全文在 git（`git log -- report/report_rule.md`）。

## 執行協議

每次收到投影片相關指令，照下列順序做：

1. 讀完本檔。畫生物示意圖前，依 F-IDX 讀 `report/BIO_DRAWING_RULES.md` 的對應小節。
2. 指令含新的風格要求時，先依「新增或修改規則」處理，再動手。
3. 開 subagent 時，brief 寫上本檔路徑與要遵守的代號，叫 subagent 先讀本檔。
4. 交付前執行 `python3 tools/check_slides.py report/<簡報名稱>/ --titles`。結束碼不是 0 時，先修好。
5. 依「交付前檢查表」逐項檢查，結果寫進該簡報 `BRIEF.md` 的「規則檢查」。
6. 有未通過的項目時，不要回報完成。先修好，或告訴使用者哪一條沒做到、為什麼。

### 規則效力

- 標 **【必要】** 的一定要做。當次指令和【必要】衝突時，先問使用者。
- 其餘是預設做法。當次指令不同時，照當次指令做。
- 是否適用不清楚、而且會改變頁面內容時，先問使用者。
- 本檔與 `BIO_DRAWING_RULES.md` 同等效力；兩者和 `VISUAL_SPEC.md` 衝突時，以這兩份為準。

### 新增或修改規則

1. **先判斷範圍。** 使用者的新指令是通用做法，還是只為某一頁、某份簡報？只為某頁的（例如某張圖的配置、某個數字怎麼寫），記在該簡報的 `BRIEF.md`，不進本檔。
2. **通用的，改寫最相近的既有條文**，把新要求併進去。不要另加一條主題重疊的新條文。真的沒有相近條文時，才在該節加一條。
3. 每節以 9 條為上限。超過時，先合併同主題的條文。
4. 條文只寫原則，加一個短例子。不要把某頁的版面細節寫成規則。
5. 生物基因畫法寫進 `BIO_DRAWING_RULES.md`，並更新 F-IDX。
6. 回報使用者時，寫出改了哪一條。

## 個人風格

### W 每週報告骨架

目標：老師只看標題，就知道這週回答了什麼、下一步做什麼。

- **W-1** 每頁標題寫成這頁的結論，一句話，不寫主題名。
- **W-2【必要】標題串讀測試。** 依頁序只讀標題，要能講完整個故事。用 `check_slides.py --titles` 列出，貼進 `BRIEF.md`。串不起來時，先改標題或頁序。
- **W-3 不做封面。** 第 1 頁就是大綱：標題寫這週的主問題；內文每段一句，只用一種分法；每段配小圖示，上次會議各方向用 ✓、→、✗、暫停表示。大綱頁已接回上次會議時，不另做「上次的問題」頁。

### P 製作流程

- **P-1【必要】大綱先過關。** 動手前，同時開兩個 subagent 審查大綱：邏輯漏洞審查者（對照 L 節）與生物資訊教授（內容與術語）。整合成審查摘要，問題都解決、並經使用者確認後，才開始製作。
- **P-2** 原始檔放 `report/<YYYY_MM_DD>_slides/`，日期用開會那天。成品用 claude.ai Slides artifact。
- **P-3** 製作分工：每個大綱段落一個 subagent；交給它檔案路徑，不貼全文。另開 subagent 看渲染縮圖 review 排版。全部完成後，再開一個檢查全冊：概念先解釋再使用、前頁結論接到下頁問題、提出的問題有回答、總結沒有新內容、沒有重複或矛盾、同一概念同名同色（F-3）、示意沒被讀成實測（E-3）。
- **P-4【必要】頁尾頁碼**寫「目前頁 / 總頁數」，照 `deck.json` `order`。增刪或移動頁面時，同一次更新全部頁尾。
- **P-5 修改範圍。** 一般修改只動被指到的頁；使用者說「嚴格重新修改」才從 P-1 重跑。刪掉某個內容時，它的圖、圖例、圖說與講稿一起刪，不留孤立的提及，剩下的版面重排（F-9）。刪整頁前先 commit；要保留在計畫的內容，搬進大綱檔的「保留在計畫，不上投影片」。
- **P-6【必要】改版前備份，發佈前合併。** 重新設計前，commit 本地的大綱、`BRIEF.md` 與 `project/`；用 Artifact `read` 把線上版存到 `live_backup/`。線上版可能有使用者或留言流程改過的內容：發佈被拒、或線上和本地不同時，先讀線上最新版，把差異併進本地再發佈。

### C 結構與內容

- **C-1【必要】主軸。** 以使用者的大綱與 `meeting_record/index.md` 最新一次會議為準。擬大綱前用一句話寫出主問題，對照使用者原話。不改段落順序與意思；要改時先問。偏離主題的段落刪掉。
- **C-2** 一頁一個重點；每個大綱段落 1–2 頁。邏輯有缺口時可以自行補頁。放不下時先刪字，刪了還放不下才拆頁。
- **C-3【必要】** 區分論文主張、程式實際行為與推論；區分 nominal 與實測 purity。數字附單位，量法記在 `BRIEF.md`。
- **C-4** `BRIEF.md` 記：主軸與指定日期、來源表、收錄與排除清單（附原因）、哪些例子是假想的、數字怎麼量、術語表、每頁草圖、改版紀錄、規則檢查結果。簡報專屬的決定都記在這裡，不寫進本檔。
- **C-5 講既有工具或程式。** 先完整講基線工具的輸入、流程、輸出，再講我們的改動；改動用並排架構圖，每步標「沿用／修改／新寫」。步驟照程式實際執行順序，每步對照原碼，位置記在 `BRIEF.md`。只講基本版本，變體記在大綱。參數只寫例子值和它控制哪一步，不寫程式沒有的範圍，也不標步驟編號。
- **C-6 講論文。** 收錄標準用「論文做了什麼」定義。標出特徵在建樹的哪一步：事後挑樹、直接當輸入、放進 likelihood，或只做驗證。long read 特徵頁只放真的用 long read 的論文。拆解一個特徵時，照「資料長怎樣 → 讀出什麼訊號 → 怎麼進入建樹」三步畫。介紹 benchmark 時，畫出它把問題拆成哪些子問題，以及設計樹、輸入、藏起來的真值。自己未發表的資料不當文獻證據。
- **C-7 證據頁。** 一頁只證明一件事。真實資料和我們的設計並排，對應的 clone 同色；左標「資料實測」、右標「設計值」。真實的樹照原文的形狀畫，不自己編；數字只取 lab_report 或已核對的文獻。
- **C-8 只放想清楚的。** 做法有疑義的，直接從頁面拿掉，不留半套。只有計畫、沒有產出時，寫明做到哪一步；不做「待補」佔位框。

### L 論證邏輯

報告講什麼、照什麼順序，以 `CLAUDE.md`「交付」「開工前」「做研究時」為準，本節只寫投影片上的做法。P-1 的邏輯審查者逐條檢查本節。

- **L-1【必要】** 先接回上次會議（大綱頁就是開場，W-3）。主問題對準老師要的成果，不換成相近但不同的問題。開場只放最核心的問題。
- **L-2【必要】** 先列研究需求，再評估候選；不符合需求的只能當參考範本。benchmark 第一句先寫真值來源。
- **L-3** AI 協助得到的結論，講稿寫明自己核對了哪一部分。「沒找到」寫成「在哪些來源沒找到」。
- **L-4** 每個任務的候選方案、選擇理由、預期與實際結果都用圖呈現。

### V 驗證計畫頁

- **V-1** 驗證流程每一步都畫：輸入資料 → 軟體 → 軟體輸出 → 和真值比對 → 得分。真實資料頁沿用模擬頁的版面，並標明比對對象：single-cell 真值樹、別的工具推出的參考樹，或沒有真值的一致性檢查。不要把參考樹寫成真值。
- **V-2** 評估指標（例如 AD F-score）配示意圖，說明它在比什麼。

### T 文字

- **T-1** ASD-STE100 風格。頁面只放名詞或短語；整句、限制、但書放講稿（但講稿只講畫面上有的，S-8）。
- **T-2** 頁面文字和圖一一對應；圖沒畫出的內容不寫在頁面上。
- **T-3 不用黑話**：內部代號（C1、B04、Phase 0）、未解釋的縮寫、工具名、程式欄位名（`major_cn`）。必要術語第一次出現時，用圖或一句白話解釋。把白話說明做成頁時，恢復成生物術語（SNV、allele、copy number）。使用者指定要寫工具名時照做，講稿用一句白話說它做什麼。
- **T-4 固定用語**：

  | 不寫 | 寫 |
  |---|---|
  | 雜訊 | 具體現象，例如「VAF 估不準」 |
  | 抽（程式的隨機步驟） | 隨機亂數產生 |
  | 長讀 | long read（全冊術語記在 `BRIEF.md`） |
  | 分群、接成樹 | 寫出作用對象：SNV 分群、形成樹拓樸 |
  | 單細胞 clone（指細胞株） | 單細胞衍生 clone |
  | 有無欄位加修飾 | 只寫「有」或「無」 |

- **T-5** 本研究預設只有一個 sample。不寫「每個 sample」、多 sample 或 sample 名稱；需要比較時，比同一個 sample 內的不同 SNV。

### E 例子

- **E-1【必要】** 全冊用同一個例子貫穿，例如同一棵樹、同一組 SNV。
- **E-2** 真實例子夠小、看得懂時用真實的；太大時用很小的假想例子，真實結果放後面或講稿。
- **E-3** 假想值標「示意」，真實產出標「實際結果」，不混在同一張圖而不標。
- **E-4** SNV 用 SNV1、SNV2 命名，不用資料裡的編號（m392）。
- **E-5** 算式只用一個例子算到底。把分子、分母畫成看得到的東西（例如彈珠：總 copy number＝全部彈珠，帶突變的＝紅彈珠），算式只留一行結果。

### S 講稿

- **S-1** 先用口語帶出這頁的結論（「這頁要看的是…」），再沿著圖講原因。不念「結論：」。
- **S-2** 每頁 30 秒到一分鐘，中文約 120–250 字。
- **S-3** 用能直接念的口語。黑話規則同 T-3；不放路徑、檔名、commit 或內部代號，來源記在 `BRIEF.md`。
- **S-4** 叫觀眾看某個元素時，用位置、顏色和上面的字指路（「左邊藍色這張」），只講它上面看得到的東西。
- **S-5** 段落之間要橋接：上一頁結尾用一句話帶出下一段的問題，下一頁開頭的結論回答它。段落內的頁，接得自然才接。
- **S-6** 假想例子和推論要說出來（「舉個例子」「這是我們的推論」）。同一個但書全冊只講一次。
- **S-7** 講流程照步驟順序，一步講完再講下一步。
- **S-8【必要】講稿只講畫面上有的東西。** 畫面上沒有的背景、程式細節、限制記在 `BRIEF.md`。本條優先於其他「放講稿」的條文。

### F 圖

- **F-1 先構圖再畫。** 先查 `VISUAL_SPEC.md`；沒有的概念，開 subagent 搜參考構圖。在 `BRIEF.md` 用 ASCII 畫草圖：誰和誰比、哪裡沒有、結論是什麼。版面有兩種以上合理做法時，先畫給使用者選。舊 PPT 的圖只作參考。
- **F-2【必要】圖 80%、文字 20%。** 每頁一張主圖，佔內容區約 80%，圖外文字約 80 字以內。風格照學習網站（`research/literature/surveys/tumor_evolution_history_2026-11-05/site/`）：細胞畫成圓、染色體畫成橫條、突變是紅星、檔案畫成文件、流程畫成箭頭與階梯。條列（優缺點、需求、已確認／未確認）也改成圖示加 ✓／✗。不要做成「方框裡兩行字」的文字卡。交付前把圖文比例寫進 `BRIEF.md`。
- **F-3【必要】同一概念全冊同色、同圖示。** 固定配色：

  | 類別 | 顏色 |
  |---|---|
  | HP1 | `#2C5F9E` |
  | HP1-1（HP1 上帶 SNV） | `#8FB3E0` |
  | HP2 | `#D9772B` |
  | HP2-1（HP2 上帶 SNV） | `#F2B880` |
  | somatic SNV | `#D23A2E` |
  | unphased | `#9AA3AE` |

- **F-4 比較。** 兩個東西比較時左右並排，同一列放同一件事（基準在左）。比例要每個樣本都標出兩邊的數字與顏色（例如 HP1 52.7%、HP2 47.3%），不只給一個數字。單位要和對照的一邊一致。結果用 ✓／✗ 加文字，不只靠顏色；基準沒有的東西用斜線底。
- **F-5 流程圖。** 每一步配一張示意圖，畫出這一步產生的東西；不跳過中間的資料轉換。每步只留核心：一句白話寫「做了什麼處理」，加一個關鍵數字，不用黑話（例：「去掉不可靠的突變」，不寫「VAF ≥ 0.25、QUAL ≥ 20」）；細節放講稿或 `BRIEF.md`。一頁裝兩件事時依問題拆頁（例：先「怎麼建」，再「怎麼驗證」）。主流程用實線，回饋或人工介入用虛線。分屬兩個程式時，用兩個大框，中間畫傳遞的資訊。逐一處理資料的演算法，只畫前幾步讓人看懂規則，再畫最後結果。
- **F-6 隨機。** 隨機規則寫在頂部一列；隨機產生的事件旁放骰子，結果旁標隨機值與機率（上下式分數）；固定的不放。抽象分布（例如 Dirichlet）旁畫生活比喻小圖。
- **F-7 時間順序。** copy number 事件和 SNV 的先後，畫成「事件前 → 事件 → 事件後」；事件後才出現的 SNV 只畫在事件後。
- **F-8** 困難情境、陷阱或限制，每一項都畫出發生原因的機制示意圖，細則見 `BIO_DRAWING_RULES.md` D 節。
- **F-9** 刪掉內容後重排版面：剩一張卡就放大置中，剩多張就平分寬度，不留大片空白。
- **F-IDX 生物基因畫法細則索引。** 圖含下列關鍵字時，先讀 `BIO_DRAWING_RULES.md` 對應小節：

  | 關鍵字 | 小節 |
  |---|---|
  | read 位點、alt／ref 圖例、SNV 名稱（SNV1、SNV2） | A |
  | IGV、read 堆疊、read 層資料、HP1／HP2 分區 | B |
  | 演化樹、clone tree、設計樹／真值樹、軟體輸出樹、節點 CCF | C |
  | subclonal CN、copy number、低 purity、低深度、陷阱或限制的機制圖 | D |

## 交付前檢查表

### 腳本檢查

`python3 tools/check_slides.py report/<簡報名稱>/ --titles` 檢查每一頁的頁面與講稿：

| 代號 | 腳本抓什麼 |
|---|---|
| P-4 | 頁尾「n / N」和 `deck.json` `order` 不一致，或沒有頁尾（舊簡報 id 為 `cover` 的第 1 頁除外）。 |
| T-3 | 內部代號（C1、B04、Phase 0 等）與程式欄位名（`major_cn` 等）。 |
| T-4 | 「雜訊」、「抽」（「抽象」除外）、「長讀」。 |
| T-5 | 「每個 sample」「多 sample」、s0 這類 sample 名稱。 |
| E-4 | m392 這類 SNV 編號。 |
| S-3 | 講稿裡的路徑、檔名與 commit 編號。 |

使用者批准的例外，在該頁 HTML 加 `<!-- lint-allow 代號: 理由 -->`，理由寫批准日期。腳本漏抓、使用者修正過兩次的錯，加進腳本的 `RULES`。

### 人工檢查

先照 CLAUDE.md 交付 5 跑最新會議 summary §2.2 清單。再把下表複製到 `BRIEF.md`「規則檢查」，每項填 ✓、✗ 或「不適用」，✗ 寫頁碼與原因。局部修改時只查被改的頁，但 W-2 與 E-1 一定查全冊。

| 代號 | 檢查什麼 |
|---|---|
| W-2 | 只讀標題能講完故事；標題清單已貼進 `BRIEF.md`。 |
| P-1 | 大綱已經兩方審查，並經使用者確認。 |
| P-6 | 改版前本地與線上都已備份；發佈前已併入線上的改動。 |
| C-1 | 段落順序與意思和使用者大綱一致；主問題對照過原話。 |
| C-3 | 每個 claim 分得出論文、程式或推論；purity 寫明 nominal 或實測。 |
| L | 頁序照 CLAUDE.md 交付 1–4。 |
| E-1、E-3 | 全冊同一個例子；示意標「示意」，實測標「實際結果」。 |
| F-2 | 每頁主圖約 80%，圖外文字約 80 字內；量測結果在 `BRIEF.md`。 |
| F-3 | 配色照固定表；同一概念同色、同圖示。 |
| T-2、T-3 | 頁面文字都有對應的圖；腳本抓不到的黑話已處理。 |
