# 報告與投影片規則

本檔是製作與修改投影片報告的規則。讀者是負責做簡報的 agent 與 subagent。

報告對象是指導老師與實驗室成員。老師會追問主問題有沒有對準、證據從哪裡來（見「L 論證邏輯」）。所以本檔的重點是：邏輯先過關，再做頁面。

## 執行協議

每次收到投影片相關指令，照下列順序做：

1. 讀完本檔全文。畫生物示意圖前，再依「F-IDX」讀 `report/BIO_DRAWING_RULES.md` 的對應小節。
2. 指令含新的風格要求時，先依「新增或修改規則」寫進本檔，再動手。
3. 開 subagent 時，在 brief 寫上本檔路徑，並列出這個 subagent 要遵守的條文代號（例如 `F-4`、`S-6`）。叫 subagent 先讀本檔。
4. 交付前，執行 `python3 tools/check_slides.py report/<簡報名稱>/ --titles`。結束碼不是 0 時，先修好再往下做。
5. 依「交付前檢查表」的人工項目逐項檢查。結果寫進該簡報 `BRIEF.md` 的「規則檢查」一節。
6. 腳本或檢查表有錯誤時，不要回報完成。先修好，或向使用者說明哪一條沒做到、為什麼。

### 規則效力

- 標 **【必要】** 的條文一定要做。
- 其餘條文是預設做法。當次指令和預設不同時，照當次指令做。
- 當次指令和【必要】條文衝突時，先問使用者。不要自行跳過【必要】條文。
- 寫「可以」的條文是選用。
- 同一主題有兩條規則時，以本檔寫的最後狀態為準。本檔不保留「舊版作法」。
- 條文是否適用不清楚、而且會改變頁面內容時，先問使用者。

### 文件之間的優先順序

1. 本檔與 `report/BIO_DRAWING_RULES.md` 同等效力。
2. 這兩份和 `report/VISUAL_SPEC.md` 衝突時，以這兩份為準。
3. 單份簡報的主軸、收錄清單與術語，記在該簡報的 `BRIEF.md`。

### 新增或修改規則

1. 找到對應區塊。生物基因畫法規則寫進 `report/BIO_DRAWING_RULES.md`，再更新「F-IDX」索引。
2. 先找有沒有同主題的舊條文。有的話，直接改寫舊條文成最新狀態，不要另加一條互相打架的新條文。
3. 新條文用該區塊的下一個代號。不要重新編號既有條文，其他文件會引用代號。
4. 條文結尾寫日期，例如「（2026-10-21 加入）」或「（2026-10-21 修改）」。
5. 回報使用者時，寫出新增或修改的條文代號。

## 個人風格

### W 每週報告骨架

每週報告的目標：老師只看標題，就知道這週回答了什麼、下一步做什麼。（2026-10-21 加入）

- **W-2** 每頁標題寫成這頁的結論（C-8），而且只寫一句。
- **W-3【必要】標題串讀測試。** 依頁序只讀全部標題，要能講完整個故事。用 `tools/check_slides.py --titles` 列出標題，貼進 `BRIEF.md` 的「規則檢查」。標題串不起來時，先改標題或頁序，再改內容。
- **W-4 不做封面。** 第 1 頁直接寫這週的大綱文字（2026-10-23 加入）：
  - 標題寫這週的主問題（C-2）。
  - 內文依頁序列出這週要講的段落，每段一句，寫這段回答什麼。只用一種分法（C-5）。
  - 這頁只放文字，不用配圖（T-6 例外）。
  - 報告日期與簡報名稱放頁尾，和其他頁相同。
  - 大綱頁的主問題就是上次老師的問題時，大綱頁本身就是 L-1 的開場。不要再另做一頁「上次的問題」，兩頁會講同一件事。上次問題的答案來源（例如生成程式公開、重跑相同）放進講稿或後面的流程頁。（2026-10-23 修改，使用者刪掉和大綱頁重複的第 2 頁）

### P 製作流程

- **P-1【必要】大綱審查。** 動手製作前，同時開兩個 subagent 審查使用者的大綱：
  - **邏輯漏洞審查者**：找故事邏輯的缺口、跳躍、矛盾，以及提出後沒有回答的問題。逐條對照「L 論證邏輯」。
  - **生物資訊教授**：檢查生物與演算法內容是否正確、術語是否用對、論證是否站得住。

  審查規則：
  - 兩位都看完整大綱，各自給建議。
  - 先看故事主軸。整份大綱要有一個主問題，每段都要推進它。段落只是並列、和主問題無關時，判為發散。
  - 整合兩位的意見，寫成一份審查摘要，交給製作的 subagent。
  - 兩位的問題都解決後，才開始製作。有未解決的問題時，修改大綱，再審查一次。修改大綱時遵守 C-1。
- **P-2【必要】** 大綱邏輯先經使用者確認通過，才可以製作或修改報告。
- **P-3** 投影片原始檔放在 `report/<簡報名稱>/`。不要放在 `research/` 或暫存目錄。
  - 簡報名稱用報告日期，格式 `YYYY_MM_DD_slides`。使用者說「下星期三」時，用下次開會那天的日期，不用製作當天的日期。（2026-10-21 加入）
- **P-4** 用 `/slides`（claude.ai Slides artifact type）製作最終成品。
- **P-5** 每個大綱段落用一個 subagent 製作該段全部頁面。不要每一頁各開一個 subagent。另開一個 subagent review 內容與排版。
  - 交給 subagent 的是檔案路徑（大綱、審查摘要、`BRIEF.md`、本檔），不要貼全文。subagent 只回摘要與檔案位置。
  - review 排版時，看渲染出來的縮圖。不要把整份原始碼讀進 context。
- **P-6** 全部段落完成後，另開一個 subagent 檢查全冊故事邏輯。檢查項目：
  - 每個概念在使用前已經解釋過。
  - 前一頁的結論能接到下一頁的問題。
  - 前面提出的問題，後面有回答。
  - 總結沒有出現前面沒講過的新內容。
  - 頁與頁之間沒有重複或互相矛盾。
  - 同一概念全冊用同一個名稱、顏色與圖示（F-4）。
  - 假想的例子與數值沒有被讀成實測（E-3）。

  依檢查結果修改後，才算完成。
- **P-7【必要】頁尾頁碼照真實頁數顯示**，寫成「目前頁 / 總頁數」。目前頁是該頁在 `deck.json` `order` 中的位置，第 1 頁是大綱頁（W-4），也要放頁尾。總頁數是 `order` 的長度。新增、刪除或移動頁面時，同一次修改就更新全部頁尾。不要沿用大綱預計的頁數。（2026-10-20 加入，2026-10-23 修改）
- **P-8** 修改既有報告的範圍：
  - 一般修改只動被指到的頁，不重跑整個流程。
  - 使用者要求「嚴格重新修改」時，從 P-1 重跑完整流程。逐頁對照本檔檢查，違反的地方全部改掉，不要只修局部。
- **P-9** 使用者要刪掉某頁、但保留其中做法到計畫時（2026-10-20 加入）：
  1. 從 `deck.json` `order` 移除該頁，同一次更新全部頁尾（P-7）。
  2. 把該頁的做法、預期、限制與講稿原文搬進該簡報的大綱檔。標成「保留在計畫，不上投影片」，並寫刪除日期。
  3. 把原頁檔移到簡報目錄的 `removed_slides/`。不要直接刪除。
- **P-10** 使用者要求刪掉某個特徵或做法時（例如 pair），同一頁的圖、圖例、圖說與講稿一起刪。不要留下孤立的提及。（2026-10-20 加入）
- **P-11【必要】** 重新設計既有簡報前，先備份舊版（2026-10-21 加入）：
  1. 把大綱、`BRIEF.md`、`project/` 與 `removed_slides/` 複製到簡報目錄的 `old_v<版本>_slides/`。
  2. 線上版也要備份。用 Artifact `read` 把線上版的 `project/` 檔案存到同目錄的 `live_backup/`。線上版可能有使用者在編輯器裡改過、本地沒有的內容。
  3. 備份完成後，才可以覆寫原檔。

### C 結構與內容

- **C-1【必要】** 以使用者給的大綱為主軸。不要改動大綱段落的順序與標題意思。需要改動時，先問使用者。
- **C-2【必要】** 主軸以使用者指定的主題為準。主題的大方向，以 `research/meeting_record/` 裡最近一次的會議整理為準。擬大綱前，用一句話寫出主問題，對照使用者的原話與會議整理。製作途中不確定主軸時，回頭讀該會議整理。偏離主題的段落直接刪掉。（2026-10-21 修改）
- **C-3** 頁數控制：
  - 每個大綱段落放 1–2 頁，以減少製作 token。
  - 大綱邏輯有缺口時，自行加頁補足。加的頁放在大綱對應段落內。
  - 文字放不下時，先依 T-8 刪字。刪字後仍放不下才拆頁。
  - 例外：C-12 的特徵拆解頁可以超過 2 頁。
- **C-4** 每頁只講一個重點。內容要簡單。
- **C-5** 議程頁只用一種分法說明接下來的內容（例如三個子問題）。不要再用第二種分法重講一次。卡片上不標段落編號。
- **C-6** 內容主要取自近期的建樹研究 session 與 repo 文件。
- **C-7【必要】** 區分論文主張、程式實際行為與分析推論。區分 nominal purity 與實測 purity。
- **C-8** 標題可以寫成這頁的結論，一句話講完，不寫成主題名。
- **C-9** 數字附單位。量測方式記在 `BRIEF.md`。
- **C-10** `BRIEF.md` 記錄：
  - 來源代號表，每個來源只列一次。
  - 哪些例子與數值是假想的。
  - 數字怎麼量的。
  - 哪些是論文主張、程式行為或分析推論。
  - 每頁圖的草圖（F-1）。
  - 術語表（B-7）。
  - 規則檢查結果（交付前檢查表）。
- **C-11** 介紹論文用哪些特徵建樹時，每篇標明特徵進入建樹的哪一步（2026-10-20 加入）：
  - 事後挑樹：先由別的工具產生候選樹，再用特徵挑一棵。
  - 直接當建樹的輸入，例如距離分群。
  - 放進機率模型（likelihood）。
  - 只做驗證，不參與建樹。

  不要把「事後挑樹」寫成「用特徵建樹」。
- **C-12** 總覽頁講得太淺時，每個特徵各用一頁拆解。每頁用同一套三步驟版面（2026-10-20 加入）：
  1. 資料長怎樣：read 上看到什麼。
  2. 讀出什麼訊號：為什麼能推出先後或親緣。
  3. 怎麼進入建樹：接到哪個工具或模型。

  每一步配一張示意圖，文字只當圖說。細節數字先不放頁面。限制放講稿。
- **C-13** 介紹 long read 特徵的頁，只放真的用 long read 資料的論文。短讀方法即使概念可以移植，也不放進這類頁。（2026-10-20 加入）
- **C-14** 把對話中的說明做成頁時，保留原說明的結構，例如兩種做法各一欄。每個重點畫成一張流程示意圖。頁面只放短語，完整說明放講稿。（2026-10-20 加入）
  - 原說明是給非專業者的白話版時（例如「錯字」「副本」），頁面與講稿恢復成生物術語（SNV、allele、copy number、mutation loss 等）。保留白話版的步驟順序與簡單例子。術語第一次出現時照 T-5 用一句話解釋。（2026-10-22 加入）
- **C-15** 研究計畫頁只放做法已經想清楚的部分。使用者覺得做法有疑義或「怪怪的」時，直接從頁面刪除，不留半套說明。（2026-10-20 加入）
- **C-16** 介紹 benchmark（例如 SMC-Het）時，用一頁畫出它把建樹問題拆成哪幾個子問題（2026-10-21 加入）：
  - 每個子問題一張卡，寫「問什麼」與「輸出什麼」，配一張示意圖。卡片依推理順序排。
  - 同頁列出 benchmark 的資料：設計樹的來源與數量、給方法的輸入、藏起來的真值。
  - 取得方式與限制放講稿。
- **C-17** 論文用某個特徵建樹、又有 single-cell 真值樹時，同一頁並排畫「特徵建出的樹」與「single-cell 真值樹」。對應的 clone 用同一種顏色。寫明特徵取自哪個基因區域，例如 PCDH 區的甲基化。真值樹照論文原圖的形狀畫，不要自己編。（2026-10-21 加入）
- **C-18** 說明某個程式的資料生成流程時（2026-10-21 加入）：
  - 正確：每一步對照程式原碼核對，程式位置記在 `BRIEF.md`。論文寫法和程式行為不同時，分開標示。
  - 清楚：照程式實際執行順序，一步一張卡。每張卡畫一張示意圖，畫出這一步的輸出（F-9）。「輸入 → 做什麼 → 輸出」寫在講稿與大綱。（2026-10-23 修改）
  - 好理解：例子的選法照「E 例子」。
  - 流程的每一步都要有展開頁，包括「定參數」這類設定步驟。總覽頁的一張卡不能取代展開頁。展開頁寫出每個參數怎麼隨機產生、範圍多少、例子值多少。（2026-10-22 加入，使用者指出第 0 步定參數被遺漏）
  - 參數展開頁也照 F-9 畫成示意圖。每個參數標出它控制後面哪一步、影響什麼。會改變多個輸出的參數（例如 WGD），另畫細節：每個選項放在哪個 clone、各選項的出現機率，以及對 copy number、multiplicity、VAF、depth 的影響。影響要對照程式原碼核對。（2026-10-23 加入）
  - 參數卡不標步驟編號（例如「→ 第 2 步」），標題也不用「第 N 步」排參數，否則觀眾會以為參數有先後順序。只寫參數控制什麼，並在講稿說明參數之間沒有先後。（2026-10-23 加入，使用者留言）
  - 參數不寫「範圍」。程式沒有寫死範圍的參數（例如從摘要表隨機選值），不要把表裡的最小、最大值寫成範圍。只寫例子值，以及它控制哪一步。（2026-10-23 加入，使用者指出 purity 0.21–0.81 不是程式的固定範圍）
  - 放置位置隨機的 copy number 事件（例如 WGD 隨機放在 main clone 或一個 subclone），畫在流程中放這個事件的那一步（例如「放事件」頁），不畫在定參數頁；定參數頁只留參數卡。只挑幾個 clone 要畫清楚：候選 clone 用虛線圈標出，被挑中的加事件膠囊與骰子。（2026-10-23 修改）每個選項畫一棵樹，事件畫成枝上的膠囊（和 SNV 放在枝上同一種畫法），受影響的 clone 用灰底框起來，並寫明「隨機選」。（2026-10-23 加入）
  - 參數細節頁只放使用者指定的區塊。使用者刪掉某個示意圖（例如 WGD 的三棵樹）時，連同它的圖例與只解釋它的文字一起刪（P-10）。（2026-10-23 加入）
  - 程式有基本版本與變體（例如 CONIPHER 生成器的 No-Noise 組與 Noise 組）時，只講基本版本。變體的步驟（例如 mutation loss、假 SNV）不上頁面也不進講稿，記在大綱的「保留在計畫，不上投影片」。使用者要求時再加。（2026-10-22 加入）

### L 論證邏輯

來源：2026-10-21 開會時老師指出的邏輯問題，整理見 `research/meeting_record/2026_10_21_meeting_summary.md` 第 2 節。P-1 的邏輯漏洞審查者逐條檢查本節。

- **L-1【必要】先回答老師上次的問題。** 報告開頭先放上次會議的問題與本次答案，再報新進度。大綱頁（W-4）已寫出這個問題時，大綱頁就算開場，不另加頁。（2026-10-23 修改）
  - 主問題對準老師要的成果，不要換成相近但不同的問題。例如老師要「怎麼產生資料」，不要改報「資料存不存在」。
  - 開場只放最核心的問題。後面段落會完整回答的問題，不要在開場和總結先列一次。（2026-10-21 加入）
- **L-2【必要】先列研究需求，再評估候選。** 介紹任何資料、benchmark 或方法前，先放需求清單，例如必須是 long read、必須有真值。每個候選逐條對照需求，寫明符合或不符合。不符合需求的候選只能當參考範本，不能當驗證資料。
- **L-3【必要】每提一個 benchmark，第一句先說真值來源**：模擬、single cell，或其他來源。同時寫讀長，以及有沒有公開的生成程式。
- **L-4「程式存在」不等於「程式適用」。** 說某段程式可以沿用前，先讀過程式。逐項寫它產生什麼、缺什麼，並標出程式位置。
- **L-5 AI 的說法不是證據。** 「可行」「沒有」「已驗證」這類結論都要附論文、程式或實測來源。AI 協助得到的結論，寫明自己核對過哪一部分。
- **L-6「沒找到」不能寫成「不存在」。** 寫成「在 X 範圍內沒找到」，並附搜尋來源、關鍵字、時間範圍與篇數。
- **L-7 先列出所有路徑，再收斂。** 例如驗證路徑有模擬與 single cell 兩條。先兩條都列出，再說明選哪條、為什麼。
- **L-8 流程要能脫稿講完。** 資料生成或分析流程用「輸入 → 步驟 → 輸出 → 假設」四欄寫在大綱與講稿。頁面照 F-9 畫成示意圖，不放四欄文字表格。每步標「沿用」或「新寫」。（2026-10-23 修改）
- **L-9 能展示成果時，放實際產出。** 例如真值樹、輸出檔前幾行、一張分布圖。只有計畫、沒有產出時，在頁面寫明目前做到哪一步。
- **L-10** 介紹既有工具（例如 PhyClone）時，先完整講它本身的輸入與流程，再提出我們的新需求（例如 long read）。不要在講完基線工具之前放新需求頁。（2026-10-21 加入）
  - 使用者要求先把基線工具講好時（例如「long read先不要想」），整份簡報只講基線工具，不放新需求頁與改造頁。這些內容記在大綱的「保留在計畫，不上投影片」。（2026-10-22 加入）

### V 驗證計畫頁

- **V-1** 畫驗證流程時，每一步都畫出來，不能跳步。至少要有：輸入資料 → 軟體 → 軟體輸出的結果 → 和真值比對 → 得分。（2026-10-20 加入）
- **V-2** 評估指標（例如 AD F-score、V-measure）配示意圖，說明它在比什麼。不要只寫指標名稱。（2026-10-20 加入）
- **V-3** 驗證計畫分「模擬資料」與「真實資料」時，真實資料頁沿用模擬頁的流程版面（V-1）。在圖上標明比對對象：single-cell 真值樹、別的工具推出的參考樹，或沒有真值的一致性檢查。不要把參考樹寫成真值。（2026-10-20 加入）

### B 各簡報主軸

每份簡報的主軸、收錄清單與篇數，記在該簡報的 `BRIEF.md`，不寫在本檔。本檔只放通用規則。

- **B-1 主軸**：使用者指定主軸時，記下指定日期、分幾段、每段回答什麼問題。之後的大綱都以它為準（C-2）。
- **B-2 收錄標準**：用「論文做了什麼」定義，不用論文名稱定義。例如「至少用一個建樹工具」：
  - 現成軟體或自己的演算法都算。
  - 只做 VAF 分群、畫圖或人工整理的樹不算。
- **B-3 排除與追加**：使用者點名排除或加入的論文，寫進 `BRIEF.md` 的清單並附原因。符合標準但使用者不收的論文也要記。
- **B-4 篇數**：以「符合標準的論文，扣掉排除清單」計算。篇數只記在 `BRIEF.md`。
- **B-5 加入或移除論文時**：
  - 引用篇數、計數或結論的頁一起改，不留下前後矛盾。
  - 改變主結論時，先問使用者。
  - 新論文的但書全冊只講一次（S-9）。
- **B-6 資料範圍**：我們自己未發表的資料，不當成文獻證據。已發表論文的資料（包含細胞株）可以列。
- **B-7 用語**：同一份簡報的術語統一，並記在 `BRIEF.md` 的術語表。例如全冊用「long read」，不用「長讀」。（2026-10-20 使用者指定）

### T 文字與表格

- **T-1** 文字用 ASD-STE100 風格。少用長段文字。
- **T-2** 有或無的欄位只寫「有」或「無」。不加「部分強」之類的修飾，也不加旁邊小字。
- **T-3** 定序平台欄位照該簡報 B-7 的術語表寫，例如「long read」或「短讀」。再寫有無 BAM 可下載。（2026-10-21 修改，配合 B-7）
- **T-4** 判斷論文有無 single-cell ground-truth 演化樹時，以 PhyClone 的 sc 演化樹為標準。
- **T-5** 不用觀眾不懂的黑話。黑話包括：
  - 內部代號，例如 C1、B04、K10、F1、C0、Phase 0。
  - 未解釋的縮寫，例如 PS、CP、AD、sc3、1A。
  - 工具名，例如 Battenberg、MuTect。
  - 程式欄位名，例如 tumour_content、major_cn。

  必要的術語在第一次出現時，用圖或一句白話解釋。使用者指定要標工具名時照做，並在講稿用一句白話說明它做什麼，例如「PyClone-VI 依突變比例分群，ClonEvol 排出候選樹」。（例外於 2026-10-20 加入）
- **T-6** 頁面文字和圖一一對應：每個重點文字都有對應的圖。圖沒畫出的內容不寫在頁面上。
- **T-7** 補充說明、限制、但書與推論細節放講稿，不放頁面。
- **T-8** 文字太小看不清時，先刪字，不要縮小字級。刪字後仍放不下，照 C-3 拆頁。
- **T-9** 圖中文字只放名詞或短語。整句放講稿。
- **T-10** 不用「雜訊」這類抽象詞。改寫成觀眾看得懂的具體現象，例如「VAF 估不準」。（2026-10-20 加入）
- **T-11** 步驟與術語名稱寫出作用對象。（2026-10-21 加入）

  | 不寫 | 改寫 |
  |---|---|
  | 分群 | SNV 分群 |
  | 接成樹 | 形成樹拓樸 |
  | clone 比例 | 填每個 clone 的 CCF（CCF＝自己＋所有後代） |
- **T-12** 本研究預設只有一個 sample。頁面與講稿不寫「每個 sample」，也不提多 sample 或 sample 名稱（例如 s0、s3）。需要比較時，改比同一個 sample 內的不同 SNV。（2026-10-21 加入）
- **T-13** 描述程式的隨機步驟時，不用「抽」。一律寫「隨機亂數產生」，例如「隨機亂數產生拷貝數」。（2026-10-21 加入）

### E 例子

本節統一全冊例子的選法。C-18、F-12、F-13 都照本節。（2026-10-21 整合）

- **E-1【必要】全冊用同一個例子貫穿**，例如同一棵樹、同一組 SNV。不要只改一頁，造成前後頁例子不一致。
- **E-2** 選例子的順序：
  1. 真實產出的例子夠小、觀眾看得懂時，用真實例子。不要自己編數值。
  2. 真實例子太大、頁面變複雜時，改用一個很小的假想例子，例如 10 個 SNV 分成 4 群。真實結果放講稿，或放在 F-12 的「全部跑完的結果」段。
- **E-3** 假想的例子與數值在頁面標「示意」。真實產出的數值在圖上標「實際結果」。兩者不混在同一張圖而不標。
- **E-4** 不拿資料裡的 SNV 編號（例如 m392、m8）當例子，觀眾看不懂。改用 SNV1、SNV2 這類名稱（見 `BIO_DRAWING_RULES.md` A 節）。
- **E-5** 公式頁只用一個例子算到底，例如期望 VAF 只用 SNV6。同一頁的其他例子（其他 SNV）先不顯示，同頁後面的步驟（例如 read count）也改用同一個例子。（2026-10-23 加入）
  - 不用公式表呈現。把分子、分母畫成看得到的東西（照 F-14 的比喻）。期望 VAF 用彈珠：總 copy number＝全部彈珠數，帶 SNV 突變的 copy 數＝紅色彈珠數，以 100 個細胞計數。normal 的彈珠也要畫進去。算式只留一行結果。（2026-10-23 修改，使用者覺得逐列「比例 × 份數」表太公式；層蛋糕試過後改成彈珠）
  - 下一步的 read count 沿用同一個罐子：depth＝抽幾次（每次放回），alt＝抽到紅彈珠幾次。畫出罐子、抽的動作、抽出的彈珠，再接 alt／ref 長條。（2026-10-23 加入）
  - read count 區塊要明寫：抽到紅彈珠（alt read）的機率，就是前一步算出的期望 VAF。頁面圖上標一句，講稿也說一次。（2026-10-23 加入）
  - 改版前先在 `BRIEF.md` 用 ASCII 畫 2 個以上的方案給使用者選（F-1 第 3 步），選定後才改頁面。（2026-10-23 加入）

### S 講稿

- **S-1** 講稿只講重點。先講這頁的結論，再沿著圖講原因。
- **S-2** 每頁講稿約一分鐘，中文約 200–250 字。
- **S-3** 用口語寫，能直接念出來。可以用「我們」「大家看這裡」。
- **S-4** 黑話規則同 T-5。
- **S-5** 講稿不放 repo 路徑、章節編號或內部代號。來源記在 `BRIEF.md`。
- **S-6** 講稿叫觀眾看某個圖元素後，只講該元素上看得到的東西。用位置、顏色與上面的字指路，例如「左邊藍色這張」。不要改用另一個元素的編號。要講另一個元素時，先把觀眾的視線移過去，例如「再看最下面這條」。
- **S-7** 頁與頁之間的橋接：
  - 段落之間必須橋接。上一頁結尾用一句話說明下一段為什麼和這頁有關，再提問。下一頁開頭的結論直接回答這個問題。
  - 同一段落內的頁可以用一句話接到下一頁的問題。接不自然就不寫。
- **S-8** 講到假想例子或推論時，用口語說清楚，例如「舉個例子」「這是我們的推論，論文沒有這樣寫」。
- **S-9** 同一個但書全冊只講一次，放在第一次需要的那頁。
- **S-10** 講流程時，照步驟順序講，一步講完再講下一步。不要先提後面的步驟再倒回來。（2026-10-21 加入）

### F 圖

- **F-1** 畫圖順序：
  1. 先查 `report/VISUAL_SPEC.md`。概念已在該檔時，照它的構圖與易錯點畫。
  2. 該檔沒有的概念，開一個 subagent 搜尋精確描述與參考示意圖。多份簡報會用到時，把結果加進 `VISUAL_SPEC.md`。
  3. 在 `BRIEF.md` 用 ASCII 或幾行文字畫草圖：誰和誰比、哪裡沒有、結論是什麼。
  4. 結構確認後才畫細節。
- **F-2** 優先畫簡易示意圖，不要整頁都是文字。用生物基因示意圖呈現概念，例如染色體、haplotype、read、SNV、clone tree。
- **F-3** 舊 PPT 的圖只作參考。不要整批複製舊圖。
- **F-4【必要】** 同一概念全冊同色、同圖示。haplotype read 用下列固定配色：

  | 類別 | 顏色 |
  |---|---|
  | HP1 | `#2C5F9E` |
  | HP1-1（HP1 上帶 SNV） | `#8FB3E0` |
  | HP2 | `#D9772B` |
  | HP2-1（HP2 上帶 SNV） | `#F2B880` |
  | somatic SNV | `#D23A2E` |
  | unphased | `#9AA3AE` |
- **F-5** 對照圖：
  - 兩個東西要比較時，可以用左右兩欄：左邊放基準，右邊放新做法，同一列放同一件事。例如預設做法對新方法、論文主張對實際行為、nominal purity 對實測 purity。單一概念不硬湊對照。
  - 基準那側沒有的東西用斜線底。
  - 結果用 ✓ 或 ✗ 加文字，不只靠顏色。
- **F-6** 回饋或人工介入的箭頭用虛線。主流程用實線。
- **F-7** 列出困難情境、陷阱或限制時，每一項都畫出發生原因的機制示意圖，例如資料長怎樣、為什麼推錯。不要只放名稱和圖示。完整原因放講稿。細則見 `BIO_DRAWING_RULES.md` D 節。（2026-10-20 加入）
- **F-8** 刪掉內容後頁面只剩一張卡時，把卡放大並置中，不留大片空白。（2026-10-21 加入）
  - 刪掉一張卡後剩兩張以上時，其餘的卡平分寬度、填滿版面，表格與圖跟著放大。順手把留下的卡和前面頁面的例子數值對齊（E-1）。（2026-10-23 加入，使用者刪掉輸出頁的 LTXSIM001 實際結果卡）
- **F-9** 流程頁不要過度簡化（2026-10-21 加入）：
  - 不跳過中間的資料轉換與演算法步驟，例如先建「read × 位點」矩陣，再用 UPGMA 建樹。
  - 每一步一張卡。卡上寫演算法名稱，配一張示意圖，畫出這一步當下的狀態。例如建樹時，每加入一群就畫一張當下的樹。
  - 描述任何流程時（包括總覽頁），每一步都配示意圖，畫出這一步產生的東西，例如參數、樹、比例條、read。示意圖比文字好懂。卡上文字只留步驟名稱與一個短語圖說。不要用純文字表格當流程圖。（2026-10-23 加入，使用者要求重新設計純文字的流程總覽頁）
- **F-10** 逐步重演演算法時，只畫前幾步讓觀眾看懂規則（例如前 4 步），接著直接畫最後結果（例如最後的樹拓樸）。不要每一步都畫。（2026-10-21 加入）
- **F-11** 演算法有隨機步驟時（2026-10-21 加入，同日修改為目前版本）：
  - 隨機值的定義寫在頁面頂部的規則列，例如「新群先隨機亂數產生 k（0 到…）」。
  - 下方每張步驟卡只留標題和一句結果，例如「把 c4 接到底下」「都不接」。
  - 有隨機的步驟，在結果旁放一個 k 標籤，寫隨機值與機率，例如「k＝1，機率 1/2 → 接 c4」。結果固定的步驟不放 k 標籤。
  - 機率寫成上下式分數。分子是這次產生的值（1 種），分母是所有可能的值有幾種。
  - 各步的範圍與機率細節放講稿。
  - 隨機產生的事件或選擇（例如 WGD 從 subclone 中挑 1 個、事件隨機排先後），旁邊畫一個骰子圖示，並在圖例寫「骰子＝隨機」。位置固定的事件（例如 clonal WGD 一定放在 c1）不畫骰子。（2026-10-23 加入）
- **F-12** 說明逐一處理資料的演算法（例如中國餐廳過程的 SNV 分群）時，頁面分四段，由上往下看（2026-10-21 加入）：
  1. 第 1 個 SNV 的案例。
  2. 第 2 個 SNV 的案例。
  3. 第 3 個 SNV 的案例。
  4. 全部跑完的結果，例如 600 個 SNV 分成 9 群，每群一根長條、標 SNV 數。

  前三段各畫入座前狀態、每個選項的機率、本例結果，標「示意」。第 4 段用實際產出的數值，標「實際結果」（E-3）。
- **F-13** 流程分屬兩個有先後關係的程式時，用兩個大方框分別包住各自的步驟，方框左上角寫程式名稱。兩個方框之間畫示意圖，標出前一個程式傳給後一個程式的資訊，例如每個 SNV 屬於哪個 clone、這個 clone 的 CCF。這時頁面可以寫程式檔名。（2026-10-21 加入）
- **F-14** 抽象的隨機分布（例如 Dirichlet）在旁邊畫一張生活比喻小圖。例如 purity 是一個蛋糕，Dirichlet 是一把刀，隨機切成幾塊，每一種切法機率相同。每一塊用對應 clone 的顏色，標 clone 名稱。刀旁照 F-11 放骰子。小圖放在該分布出現的卡片內，數值與正式比例條一致。（2026-10-23 加入）
- **F-IDX 生物基因畫法細則索引。** 有日期的生物基因畫法規則在 `report/BIO_DRAWING_RULES.md`。圖含下列關鍵字時，先讀該檔對應小節再畫：

  | 關鍵字 | 小節 |
  |---|---|
  | read 位點、alt／ref 圖例、SNV 名稱（SNV1、SNV2） | A |
  | IGV、read 堆疊、read 層資料、HP1／HP2 分區 | B |

## 交付前檢查表

規則分兩類。能用腳本判斷的，由 `tools/check_slides.py` 檢查，人工不用再查。需要判斷的，人工逐項檢查。

### 腳本檢查

`python3 tools/check_slides.py report/<簡報名稱>/ --titles` 檢查每一頁的頁面與講稿（`<aside>`）：

| 代號 | 腳本抓什麼 |
|---|---|
| P-7 | 頁尾「n / N」和 `deck.json` `order` 不一致，或某頁沒有頁尾。只有舊簡報 id 為 `cover` 的第 1 頁可以不放頁尾。 |
| T-10 | 「雜訊」。 |
| T-13 | 「抽」（「抽象」除外）。 |
| T-12 | 「每個 sample」「多 sample」、s0 這類 sample 名稱。 |
| E-4 | m392 這類 SNV 編號。 |
| B-7 | 「長讀」。 |
| T-5 | 內部代號（C1、B04、Phase 0 等）與程式欄位名（`major_cn` 等）。 |
| S-5 | 講稿裡的路徑、檔名與 commit 編號。 |

使用者批准的例外，在該頁 HTML 加一行 `<!-- lint-allow 代號: 理由 -->`。理由必填，並寫使用者批准的日期。腳本漏抓、而使用者修正過兩次的錯，加進腳本的 `RULES`，不要只加文字規則。

### 人工檢查

交付或發布前，把下表複製到該簡報 `BRIEF.md` 的「規則檢查」一節。每項填 ✓、✗ 或「不適用」。✗ 的項目寫出頁碼與原因。只做局部修改（P-8）時，只檢查被改到的頁，但 W-3 與 E-1 一定要檢查全冊。

| 代號 | 檢查什麼 |
|---|---|
