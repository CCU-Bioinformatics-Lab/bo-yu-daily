# 報告與投影片規則

本檔記錄使用者對 PPT／投影片報告的個人風格。收到新的報告指令時，把它併入下方對應區塊。

## 規則效力

- 標為 **【必要】** 的條文一定要做。當次指令不能取消。
- 其餘條文是預設做法，不是死板格式。當次指令與預設衝突時，以當次指令為準。
- 條文寫「可以」的是選用。

## 個人風格

### 製作流程

1. **【必要】大綱審查（動手製作前一定要做）。** 收到使用者的大綱後，同時開兩個 subagent，各扮演一個角色審查大綱：
   - **邏輯漏洞審查者**：找故事邏輯的缺口、跳躍、矛盾，以及提出後沒有回答的問題。
   - **生物資訊教授**：檢查生物與演算法內容是否正確，術語是否用對，論證是否站得住。

   規則：
   - 兩位都要看完整大綱，並各自給出建議。
   - 整合兩位的意見，寫成一份審查摘要，交給製作報告的 subagent。
   - 大綱要通過兩位的建議才能開始製作。有角色提出的問題沒有解決時，先修改大綱補救，再審查一次。修改大綱時遵守「結構與內容」第 1 條。
   - 審查先看故事主軸：整份大綱要有一個主問題，每段都要推進這個主問題。段落之間只是並列、和主問題無關時，判為發散。
2. **【必要】** 大綱邏輯先和使用者確認通過，才可以修改或製作報告。
3. 把投影片原始檔輸出到 `report/<簡報名稱>/`。不要放在 `research/` 或暫存目錄。
4. 用 `/slides`（claude.ai Slides artifact type）製作最終成品。
5. 每一個大綱段落用一個 subagent 製作。該 subagent 負責這個段落的全部頁面。不要每一頁各開一個 subagent。另開一個 subagent review 內容與排版。
   - 交給 subagent 的是檔案路徑（大綱、審查摘要、`BRIEF.md`），不要貼全文。subagent 只回摘要與檔案位置。
   - review 排版時，看渲染出來的縮圖，不要把整份原始碼讀進 context。
6. 全部段落完成後，另開一個 subagent 檢查整份報告的故事邏輯。檢查項目：
   - 每個概念在使用前已經解釋過。
   - 前一頁的結論能接到下一頁的問題。
   - 前面提出的問題，後面有回答。
   - 總結沒有出現前面沒講過的新內容。
   - 頁與頁之間沒有重複或互相矛盾。
   - 同一概念全冊用同一個名稱、顏色、圖示（見「圖」第 4 條）。
   - 假想的例子與數值沒有被讀成實測。
   依檢查結果修改後，才算完成。
7. **【必要】頁尾頁碼一定要照真實頁數顯示**，寫成「目前頁 / 總頁數」。目前頁＝該頁在 `deck.json` `order` 中的位置（封面算第 1 頁）。總頁數＝`order` 的長度。新增、刪除或移動頁面後，同一次修改就要更新全部頁尾。不要沿用大綱預計的頁數。（2026-10-20 加入）
8. 修改既有報告的範圍：
   - 一般修改只動被指到的頁，不重跑整個流程。
   - 要求「嚴格重新修改」時，從第 1 步重跑完整流程。逐頁對照本規則檢查，違反的地方全部改掉，不要只修局部。

### 結構與內容

1. 以使用者給的大綱為主軸。不要改動大綱的順序與標題意思。需要改動時，先問使用者，不要自行改動。
2. 頁數控制：
   - 每個大綱段落放 1–2 頁，以減少製作 token。
   - 大綱的邏輯有缺口時，自行加頁補足。把加的頁放在大綱對應段落內。
   - 文字放不下時，先依「文字與表格」第 8 條刪字。刪字後仍放不下才拆頁，該段落仍盡量不超過 2 頁。
3. 每頁只講重點。內容要簡單。
4. 議程頁只用一種分法說明接下來的內容（例如三個子問題）。不要再用第二種分法（例如五段順序條）重講一次。卡片上也不要標段落編號。
5. 內容主要取自近期的建樹研究 session 與 repo 文件。
6. 區分論文主張、程式實際行為與分析推論。
7. 區分 nominal purity 與實測 purity。
8. 標題可以寫成這頁的結論，一句話內講完，不寫成主題名。
9. 數字附單位。量測方式記在 `BRIEF.md`。
10. `BRIEF.md` 記錄：
    - 來源（建代號表，只列一次）。
    - 哪些例子與數值是假想的。
    - 數字怎麼量的。
    - 哪些是論文主張／程式行為／分析推論。
    - 每頁圖的草圖（見「圖」第 1 條）。

11. 主軸以使用者指定的主題為準。擬大綱前，先用一句話寫出主問題，對照使用者的原話。大綱內容偏離該主題時，刪掉偏離的段落，不要保留。
12. 介紹論文用哪些特徵建樹時，每篇都標明特徵進入建樹的哪一步：
    - 事後挑樹（先由別的工具產生候選樹，再用特徵挑一棵）。
    - 直接當建樹的輸入（例如距離分群）。
    - 放進機率模型（likelihood）。
    - 只做驗證，不參與建樹。

    不要把「事後挑樹」寫成「用特徵建樹」。（2026-10-20 加入）
13. 總覽頁講得太淺時，每個特徵各用一頁拆解。每頁用同一套三步驟版面：
    1. 資料長怎樣（read 上看到什麼）。
    2. 讀出什麼訊號（為什麼能推出先後或親緣）。
    3. 怎麼進入建樹（接到哪個工具或模型）。

    每一步都要有一張示意圖，文字只當圖說。細節數字先不放在頁面上。限制放講稿。這種拆解頁可以讓該段超過「結構與內容」第 2 條的 2 頁上限。（2026-10-20 加入）
14. 介紹長讀特徵的頁只放真的用長讀資料的論文。短讀方法即使概念可以移植到長讀，也不要放進這類頁，以免觀眾誤會它用了長讀。（2026-10-20 加入）
15. 把對話中的說明做成頁時，保留原說明的結構（例如兩種做法各一欄）。每個重點畫成一張流程示意圖，頁面只放短語，完整說明放講稿。示意的數值或柱高要標「示意」。（2026-10-20 加入）
16. 研究計畫頁只放做法已經想清楚的部分。使用者覺得做法有疑義或「怪怪的」時，直接從頁面刪除，不要保留半套說明。（2026-10-20 加入）
17. 畫驗證流程時，每一步都要畫出來，不能跳步。至少要有：輸入資料 → 軟體 → 軟體輸出的結果 → 和真值比對 → 得分。（2026-10-20 加入）
18. 使用者要求先刪掉某個特徵或做法時（例如 pair），同一頁的圖、圖例、圖說與講稿要一起刪，不留下孤立的提及。（2026-10-20 加入）
19. 評估指標（例如 AD F-score、V-measure）要配示意圖說明它在比什麼，不要只寫指標名稱。（2026-10-20 加入）
20. 驗證計畫分「模擬資料」與「真實資料」兩部分時，真實資料頁沿用模擬頁的流程版面（第 17 條），並在圖上標明比對對象是什麼：single-cell 真值樹、別的工具推出的參考樹，或沒有真值的一致性檢查。不要把參考樹寫成真值。（2026-10-20 加入）
21. 使用者要刪掉某頁、但保留其中做法到計畫時：從 `deck.json` `order` 移除該頁，同一次更新全部頁尾頁碼（「製作流程」第 7 條）。把該頁的做法、預期、限制與講稿原文搬進該簡報的大綱檔，標成「保留在計畫，不上投影片」，並註明刪除日期。原頁檔移到簡報目錄的 `removed_slides/`，不要直接丟掉。（2026-10-20 加入）

### 各簡報主軸

每份簡報的主軸、收錄清單與篇數，記在該簡報的 `BRIEF.md`，不寫在本檔。本檔只放通用規則。

1. **主軸**：使用者指定主軸時，記下指定日期、分幾段、每段回答什麼問題。之後的大綱都以它為準（見「結構與內容」第 11 條）。
2. **收錄標準**：用「論文做了什麼」定義，不用論文名稱定義。例如「至少用一個建樹工具」：
   - 現成軟體或自己的演算法都算。
   - 只做 VAF 分群、畫圖或人工整理的樹不算。
3. **排除與追加**：使用者點名排除或加入的論文，寫進 `BRIEF.md` 的清單，並附原因。符合標準但使用者不收的論文，也照樣記錄。
4. **篇數**：以「符合標準的論文，扣掉排除清單」計算。篇數只記在 `BRIEF.md`。
5. **加入或移除論文時**：
   - 引用篇數、計數或結論的頁都要一起改，不要留下前後矛盾。
   - 改變主結論時，先問使用者。
   - 新論文的但書，全冊只講一次（見「講稿」第 9 條）。
6. **資料範圍**：
   - 我們自己未發表的資料，不當成文獻證據。
   - 已發表論文的資料（包含細胞株）可以列。
7. **用語**：同一份簡報的術語要統一，並記在 `BRIEF.md`，例如全冊用「long read」，不用「長讀」（2026-10-20 使用者指定）。

### 文字與表格

1. 文字用 ASD-STE100 風格。少用長段文字。
2. 有或無的欄位只寫「有」或「無」。不要加「部分強」之類的修飾，也不要加旁邊小字。
3. 定序平台欄位寫「長讀」或「短讀」，再寫有無 BAM 可下載。
4. 判斷論文有無 single-cell ground-truth 演化樹時，以 PhyClone 的 sc 演化樹為標準。
5. 不要用觀眾不懂的黑話。黑話包括內部代號（C1、B04、K10、F1、C0、Phase 0）、未解釋的縮寫（PS、CP、AD、sc3、1A）、工具名（Battenberg、MuTect）與程式欄位名（tumour_content、major_cn）。必要的術語在第一次出現時，用圖或一句白話解釋。
   - 例外：使用者指定要標工具名時，照指定標出，並在講稿用一句白話說明它做什麼（例如「PyClone-VI 依突變比例分群，ClonEvol 排出候選樹」）。（2026-10-20 加入）
6. 頁面文字和圖一一對應：
   - 每個重點文字都要有對應的圖。
   - 頁面文字只描述當頁示意圖呈現的事實。圖沒有畫出的內容不要寫在頁面上。
7. 補充說明、限制、但書與推論細節放進講稿，不要顯示在頁面上。
8. 文字太小看不清時，先刪字，不要縮小字級。刪字後仍放不下，依「結構與內容」第 2 條處理。
9. 圖中文字只放名詞或短語，整句放講稿。
10. 圖上不用「雜訊」這類抽象詞。改寫成觀眾看得懂的具體現象，例如「VAF 估不準」。（2026-10-20 加入）

### 講稿

1. 講稿只講重點。先講這頁的結論，再沿著圖講原因。
2. 每頁講稿控制在約一分鐘，中文約 200–250 字。
3. 用口語寫，要能直接念出來。可以用「我們」「大家看這裡」這類說法。
4. 黑話規則同「文字與表格」第 5 條。
5. 不要在講稿放 repo 路徑、章節編號或內部代號。來源記錄放在該簡報的 `BRIEF.md`。
6. 講稿叫觀眾看某個圖元素後，接著只講該元素上看得到的東西。用它的位置、顏色與上面的字指路（例如「左邊藍色這張」）。不要改用另一個元素的編號（例如看卡片時講「第一段到第五段」）。要講另一個元素時，先明確把觀眾的視線移過去（例如「再看最下面這條」）。
7. 頁與頁之間的橋接：
   - 段落之間必須橋接，不要從上一段的結論直接跳到新主題。上一頁結尾先用一句話說明下一段為什麼和這頁有關（例如「長讀為什麼可能補上這兩個陷阱」），再提問。下一頁開頭的結論要直接回答這個問題。
   - 同一段落內的頁可以用一句話接到下一頁的問題。接不自然就不寫。
8. 講到假想例子或推論時，用口語說清楚，例如「舉個例子」「這是我們的推論，論文沒有這樣寫」。
9. 同一個但書全冊只講一次，放在第一次需要的那頁，後面不重複。

### 圖

1. 畫圖順序：
   1. 先查 `report/VISUAL_SPEC.md`（全域生物示意圖規格）。概念已在該檔時，照它的構圖與易錯點畫。
   2. 該檔沒有的概念，開一個 subagent 搜尋該概念的精確描述與參考示意圖。多份簡報都會用到時，把結果加進 `VISUAL_SPEC.md`。
   3. 在 `BRIEF.md` 用 ASCII 或幾行文字畫草圖：誰和誰比、哪裡沒有、結論是什麼。
   4. 結構確認後才畫細節。
2. 優先畫簡易示意圖，不要整頁都是文字。用生物基因參考示意圖呈現概念，例如染色體、haplotype、read、SNV、clone tree。
3. 舊 PPT 的圖只作參考。不要整批複製貼上舊圖。
4. 同一概念全冊同色同圖示，不要中途更換。haplotype read 用下列固定配色區分：

   | 類別 | 顏色 |
   |---|---|
   | HP1 | `#2C5F9E` |
   | HP1-1（HP1 上帶 SNV） | `#8FB3E0` |
   | HP2 | `#D9772B` |
   | HP2-1（HP2 上帶 SNV） | `#F2B880` |
   | somatic SNV | `#D23A2E` |
   | unphased | `#9AA3AE` |

   read 位點、SNV 標示、IGV 圖、演化樹的畫法細則見第 8 條索引。

5. 對照圖：
   - 兩個東西要比較時，可以用左右兩欄：左邊放基準，右邊放新做法，同一列放同一件事。例如預設做法對新方法、論文主張對實際行為、nominal purity 對實測 purity。單一概念不用硬湊對照，直接畫一張圖。
   - 基準那側沒有的東西用斜線底表示。
   - 結果用 ✓／✗ 加文字，不只靠顏色。
6. 回饋或人工介入的箭頭用虛線，主流程用實線。
7. 列出困難情境、陷阱或限制時，每一項都要畫出發生原因的機制示意圖（例如資料長怎樣、為什麼推錯）。不要只放名稱和代表圖示。原因的完整說明放講稿。（2026-10-20 加入）細則見第 8 條索引 D 節。
8. **生物基因畫法細則索引。** 有日期的生物基因畫法規則已拆到 `report/BIO_DRAWING_RULES.md`。平時不用讀。畫的圖含下列關鍵字時，先讀該檔對應小節再畫：

   | 關鍵字 | 小節 |
   |---|---|
   | read 位點、alt／ref 圖例、SNV 名稱（SNV1、SNV2） | A |
   | IGV、read 堆疊、read 層資料、HP1／HP2 分區 | B |
   | 演化樹、clone tree、設計樹／真值樹、軟體輸出樹、節點 CCF | C |
   | subclonal CN、copy number、低 purity、低深度、陷阱或限制的機制圖 | D |

   新增這類規則時，寫進該檔對應小節並附日期，再更新本表。
