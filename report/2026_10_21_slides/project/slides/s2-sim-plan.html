這頁的結論是：我們要產生有 long read 特徵的模擬資料來驗證，因為只有模擬資料知道正確的樹，新軟體贏多少只能在這裡量。我們用計數層模擬。大家看左邊，先設計一棵樹，並且依兩條同源染色體分開畫：藍色 HP1 上有 SNV1 和 SNV2，SNV1 在主幹、SNV2 只在綠色 clone；橘色 HP2 上有 SNV3，只在紫色 clone。接著再直接產生每對突變的 read 組合計數，畫法像 IGV：上面是參考序列和三個突變位置，read 一條條往下疊，紅格是 alt，白格是 ref。read 依 HP 分成上下兩區：藍色 HP1 區帶有 SNV1、SNV2，照 alt、ref 組合分成四組；橘色 HP2 區只會看到 SNV3：兩條 read 在 SNV3 是 alt，一條全是 ref。不產生真的 read，所以跑得快，可以掃大量參數。這些計數交給新軟體，軟體也依 HP1、HP2 輸出兩棵樹，標出每個 SNV 落在哪條 haplotype、哪個 clone，再拿它和一開始設計的兩棵樹逐一比對，才算得出分數，標準沿用 PhyClone 的 AD F-score 和 V-measure。兩個指標都是以突變為單位，所以比對前先把 HP1、HP2 兩棵樹的 SNV 合併回同一組 clone，變成每個 SNV 屬於哪個 clone、clone 之間誰先誰後，再和設計的樹、和 PhyClone 的單棵樹比。不同 HP 上的兩個 SNV 算不算祖孫關係，比對前要先定規則，這部分還沒決定。最右邊沿用上一頁的標準示意圖，不是結果：重疊的圓是 AD F-score，灰色是設計的樹、藍色是新軟體，重疊越多分數越高；上下兩排色點是 V-measure，上排是設計、下排是新軟體，分群越一致分數越高。最下面是模擬時要刻意製造的三種困難情境，每格的小圖畫的是它為什麼難。左邊這格：兩個兄弟 clone 的 CCF 一樣。只看 VAF，也就是帶突變的 read 比例，分叉的真樹和排成一條直線的樹都說得通，所以容易推成直線。中間這格比的是同一個腫瘤裡兩群細胞的 CN。紅點是突變，藍色是 HP1。左邊是 main clone，每顆細胞一條 HP1、一條 HP2，CN 是 2。往右演化出 subclone，HP1 多了一份，CN 變成 3。同一個突變位置，兩群細胞的 CN 不一樣。可是 PhyClone 每個突變只能給一組 CN，只能照其中一群來算，另一群就算錯，所以 CCF 會算錯。右邊這格看兩個偏低的量。上面是 purity：腫瘤細胞少，所有突變的 VAF 一起被壓小，clone 之間的差距也變小。下面是深度：read 少，VAF 就估不準，量到的值會在真正的值附近跳來跳去。兩個箭頭匯合起來，不同 clone 的 VAF 就分不開，算出來的 CCF 也不準。這三個問題都是文獻報告過的，小圖的數字和形狀只是示意。這頁是計畫，還沒有結果。如果模擬顯示有增益，下一個問題是：在真實資料上也成立嗎？
