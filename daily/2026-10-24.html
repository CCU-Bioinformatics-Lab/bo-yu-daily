04不給 HP 資訊時，PhyClone 能還原 HP 真值樹嗎？進行中

問題

手繪的 HP 真值樹（下圖）預測：不給 HP 資訊時，PhyClone 會低估 CCF、把遺失的 SNV 放錯 clone、弄錯低 CCF clone 的位置。要用實際 run 驗證這些預測，當作之後加 HP 的基線。

做法
  • 依真值樹產生 100 個 SNV：10 種角色，每種 10 個。1 個 sample、平均 200×、purity 0.40。
  • 只給 PhyClone 現有的 8 個欄位，沒有 HP 拆分計數，也沒有 cluster 檔，由 PhyClone 自己分群建樹。
  • 兩種模式：outlier 關閉（-l 0）和開啟（-l 0.05），各跑 5 個 MCMC seed。每次 run 都做 map 和 topology-report。
  • 自寫腳本，把每棵抽樣樹簡化成幾個關鍵問題再加權統計。
結果
  • MAP 選到錯的拓樸：10 次中 9 次 MAP 是直線樹，把 C3 放在 C4 之下。但 posterior 裡直線樹只佔 36–42%，和真值形狀一致的分岔樹佔 57–63%。
  • 5 個 seed 都穩定在約 4:6，所以這是資料分不出來，不是 MCMC 沒收斂。只有一個 sample 時，兩種樹都符合 CCF 加總規則。
  • C1、C2 被合併：posterior 100%。合併後的 clone CCF 是 0.89，落在真值 1.00 和 0.80 之間。
  • s10（cnLOH 造成遺失）被併進 C3：約 99.8%。
  • s2（deletion 造成遺失）被拆到多個 clone：100%。
  • outlier 機制抓不到遺失：s2、s10 進 outlier 的比例只有 0.13–0.44%，和正常 SNV（0.13–0.49%）差不多。
解讀

這組結果指出 HP 與 read 資訊該補在哪兩處。拓樸：帶 s6 的 read 從不帶 s4，可以直接排除直線樹。遺失：seg D 的 HP2 depth 下降、HP1 上升，可以指出 s10 是 cnLOH 造成的遺失，不是低 CCF clone。另外，只看 MAP 會得到錯的拓樸結論，評估時要看 posterior。

還缺
  • 只有一份資料、一個 sample、每種角色 10 個 SNV，只能當單一案例，不代表 PhyClone 的準確率。
  • 只測了不給 HP 的基線。PhyClone 沒有欄位能收 HP 資訊，要改模型或另寫工具才能測「加了 HP 之後」。
  • --assign-loss-prob 沒測，它需要 cluster 檔和 chrom 欄。
  • 沒試第二個 sample 或 ONT 實際的 30–60× depth。
  • lab_report 目錄有 392 MB（trace.h5 與 seeds/），還沒決定要不要進 git；全部都還沒 commit。

CONIPHER 真值樹的 clone 為什麼這麼多？完成

為什麼：使用者看比較圖時發現，CONIPHER 的真值樹常把 CCF 相近的 clone 分開，clone 數很多。做了什麼：讀 TRACERx_simulation_tool 的 sequencing.py，並寫 tools/conipher_clone_resolvability.py 統計全部 150 份 No-Noise 資料。結果：每棵真值樹 clone 數中位數 19（8–29），PhyClone 實際收到的 PyClone-VI 群數中位數 8；新增 SNV ≤5 的 clone 占 33%；所有 sample 比例都是 0 的 clone 占 16%；CCF 和 parent 完全相同的占 9%（容許差 0.1 時 18%）。就算合併 CCF 相同的 clone，群數也只從 19 降到 16，所以主因是 SNV 太少的小 clone。原因：生成器先決定 clone 數，再隨機分 SNV；每個 sample 只挑 3–8 個 clone 給比例。推論：這組 benchmark 的 topology 分數有上限，來自真值定義。建議評估時加算「可辨識真值」（合併 CCF 相同的 clone、SNV 少於門檻的併入 parent），自己的生成器要設每個 clone 的最少 SNV 數。狀態：寫進 notes/05_OTHER_SIMULATORS.md 新節，沒 commit。
