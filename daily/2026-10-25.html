C4 穩健性測試：longbulksim v0.2 加三種錯誤；拓樸仍穩，但定序錯誤大於 ε 時 clone 被拆開進行中

為什麼：C4 每條矛盾 read 罰 log ε，真實資料的 HP 錯標、phasing switch、定序錯誤可能讓它選錯樹。照 C4_ROBUSTNESS_PLAN.md 在新 session 實作。做了什麼：longbulksim 升到 v0.2，加 mistag_rate、switch_rate_per_mb、base_error 三個參數（錯誤率 0 時輸出和 v0.1 逐位相同，有 sha256 測試；測試 18→27 個全過）。校正：base_error 在 HCC1395BL normal CRAM 的 37,321 個位點實測 0.40%（p99 5.3%）；switch 用 LongPhase 論文 0.13–0.16% × het SNP 約 620/Mb ≈ 1/Mb；mistag 用 HCC1395 split-HP 2.4–2.5% 代理。第 1 階段 ×10、base＋C4、ε=0.01 跑 24 個 run；第 2 階段跑 real 條件與 ε 掃描 24 個 run，再補 9 個。結果：錯誤直線樹在所有錯誤條件下都 ≤ 0.001；e0 的 3 個 run 和舊實驗逐位相同。新失效模式：base_error 3% 時 clone 被拆成 4–8 個（真值 4），因為同一 clone 的 10/01 read 在 same 假設下每條罰 log ε；ε 提到 0.1 時診斷量 same_vs_split 轉正。計畫中「整條 read 錯標會產生 n11」的預期不成立（錯標 read 移到另一條 HP 的表裡成為 n00，不建模）。狀態：補跑的 9 個 run 在掃描時仍在跑；未 commit，lab report README 未寫。
