03有沒有方法真的用長讀的 haplotype／phase set 建演化樹？目前沒有完成

問題

研究主軸是用 longphase-s 的 HP1／HP2 改善 PhyClone。要確認這個方向是不是已經有人做過，以及有沒有可以直接借用的模型。

做法
  • 4 個 subagent 平行搜尋，各負責一個角度：同 read 共現與 phasing、haplotype 專屬拷貝數、single-cell 長讀與甲基化、GitHub 與近期 preprint。
  • 統一規則：一定要有建樹步驟；排除已刪的 4 篇；每項標出長讀是「進入建樹」還是「只做驗證」。
  • 合併時自己回頭核對兩件事：肺癌長讀研究的角色（補充圖 S9 顯示長讀確實讓病人 S14 選了線性樹），以及 bioRxiv 的新 DOI 前綴 10.64898（2025-12 起啟用，正確）。
  • 使用者指定把 BitPhylogeny 收進研究目錄。PDF 下載被擋，改從 Europe PMC 取全文 XML，連公式一起轉成純文字，再寫分析筆記。
結果
  • 4 個角度的結論一致：沒有已發表的腫瘤 clone tree 方法把長讀 HP、PS 或同 read 共現放進 likelihood 或 prior。
  • 長讀相關工具只做到兩種：產生 phased 特徵（longphase-s、LongPhase-TO、Wakhan、Severus、SAVANA），或把變異放到已經建好的樹上（TreeHarmonizer）。
  • 新發現 1 篇真的讓 phasing 進入建樹：Hackett 2026（bioRxiv），用 LongPhase 把 read 分 HP，再對每條 read 的甲基化 pattern 建樹，和單細胞全基因體樹接近。材料是骨髓增生性腫瘤的血液，沒有公開程式。
  • BitPhylogeny（Genome Biology 2015）收為 M08：每條 read 的多位點 pattern 整筆只能來自一個 clone，clone 數與樹形在同一個貝氏模型裡一起推。
解讀

「把 HP／PS 接進演化樹模型」目前是空白，可以當這個研究的新穎點。BitPhylogeny 證明 read 層級共現能放進機率模型，但它沒有拷貝數、純度與 read 數模型，搬到 ONT bulk 前至少要補 5 件事（筆記裡列出）。

還缺
  • Hackett 2026 只讀到摘要層級，Methods 細節還沒核對；要不要列入分類表等使用者決定。
  • BitPhylogeny 的補充檔沒讀；論文附的 Bitbucket 程式已失效，GitHub 版沒讀。
  • 每株細胞株有多少 read 在同一 phase block 內蓋到 ≥2 個體細胞 SNV，還沒量。這決定 read 層級模型在 ONT 上有沒有資訊量。
  • 搜尋結果與 M08 都還沒 commit。

簡報規則原本要求三個角色審大綱：邏輯漏洞審查者、生物資訊教授、完全不懂生物與演算法的外行人。使用者要刪掉外行人角色；接著又指出大綱發散，要求先確認大綱邏輯再動報告。

做法

依 CLAUDE.md 的慣例，先把使用者的指令寫進 report/report_rule.md 的「個人風格」區塊，再做事。

結果
  • 刪掉「完全不懂生物與資工演算法的外行人」角色。大綱審查從三個 subagent 改成兩個，規則裡的「三位」改成「兩位」，共 3 處。

  • 「不要用黑話」「術語第一次出現要白話解釋」兩條沒動，它們是寫給觀眾的規則。
解讀

同一天的簡報重做就是照這兩條新規則跑的：先兩方審主軸，三輪通過、使用者確認後才動投影片。之後的簡報也會照這個流程。

還缺

刪掉外行人角色後，沒有角色專門檢查「詞有沒有先定義」。這次是邏輯漏洞審查者順帶抓到的，規則裡沒有寫明由誰負責。
