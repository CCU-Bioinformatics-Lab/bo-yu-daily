--- 🤖 ASSISTANT [2026-09-01T08:31:08.604Z] ---
這裡的「推導」其實分成兩件不同的事，建議拆開：

```text
T + η → φ／CCF
     （把某 clone 與所有 descendants 的 η 加總）

CN → multiplicity candidates
   （根據 CN 列出可能的 mutated-copy 數）
```

`φ／CCF` 不是從 reads 直接算出來，而是：

```text
φ_v = η_v + descendants 的 η 總和
```

例如 `A → B → C`，若：

```text
ηA = 0.5、ηB = 0.3、ηC = 0.2
```

則：

```text
φA = 1.0、φB = 0.5、φC = 0.2
```

`multiplicity` 也不是從 reads 直接挑出一個答案。以 `major_cn=3、minor_cn=1、total_cn=4` 為例，模型目前會先建立：

```text
mutation-before-CN：m = 1、2、3
mutation-after-CN： m = 1
```

之後每個 `m` 都會和 `φ`、purity、CN 一起算出預期 ALT 機率 `ξ`，再用實際的 ALT／REF read counts 評分：

```text
P(m | data) ∝ P(m | CN) × P(read counts | ξ)
```

所以更準確的流程可以寫成：

```text
T + η → φ／CCF
CN → m candidates
φ + purity + CN + m → ξ
ξ 與實際 read counts 比較 → likelihood
```

| ALT read | `read-2 + base-2`，焦點鹼基 `A` 等於 `ALT A` | 高 |

## 可能誤讀

- 「REF-supporting」只表示該 read 在此 SNV 位置讀到 REF `G`，不代表整條 read 全部都是 reference。
- 「ALT-supporting」只表示該位置讀到 ALT `A`，不代表整條 read 都是變異序列。
- 單獨各顯示一條 read，不應被解讀為 `REF=1、ALT=1` 的實際比例或 coverage。
- 原圖的 read 長度與起點是示意排版；若保留不同寬度，可能被誤認為是真實 read length。
- 目前 standalone SVG 主要依靠顏色與 `G/A` 判讀，`data-meaning` 不會在畫面上顯示；最好加上可見的 `REF-supporting`／`ALT-supporting` 標籤。

## 顏色建議

IGV alignment 預設是「匹配 reference 的 base 灰色；不匹配時依 nucleotide 著色」，其中 A 綠、C 藍、G 黃、T 紅。[IGV alignment documentation](https://igv.org/doc/desktop/UserGuide/tracks/alignments/viewing_alignments_basics/)

因此本例 `REF G → ALT A` 若要維持「IGV 原生顏色」並不會是藍色 REF。藍色=REF、綠色=ALT 可以使用，但應明確標示為：

> Explanatory encoding: blue = REF support; green = ALT support.

這也不同於 IGV VCF track 的預設「藍色=reference、紅色=alternate」。[IGV VCF documentation](https://igv.org/doc/desktop/UserGuide/tracks/vcf/)

整體結論：目前兩個 SVG 的 REF／ALT 配對正確；顏色方案可接受，但應視為本專案自訂解說編碼，並補上可見文字標籤以降低誤讀。

## 排序 caveats

- `canonical SNV row` 應放在六階段之外，作為 observation/input lane；它提供 identity、REF/ALT counts、CN 與 `rho_ASCAT`，不是候選 latent state。來源：`data.md:173–221`。
- 計算上可以畫成：

```text
T + η + z
   ↓
φ / CCF
   ↓
purity + CN + genotype/multiplicity candidates
   ↓
ξ_i(g)
   ↓
REF/ALT counts → likelihood
   ↓
prior × likelihood → posterior
```

但語意上，purity、CN、multiplicity 與 `φ/CCF` 是在同一個 `ξ`／likelihood emission 中共同作用；likelihood 又會反過來更新 `T` 與 `η`。因此建議在圖旁加一條小型 `inference ↔ model scoring` feedback，而不是宣稱單向因果流程。

- CN timing 不能被省略成單一順序。PhyloWGS 明確區分 SSM 先於 CNV、CNV 先於 SSM、以及兩者位於不同分支的情況；這些情況會改變 expected VAF。[PhyloWGS](https://pmc.ncbi.nlm.nih.gov/articles/PMC4359439/)（lines 217–240）
- purity、copy number、mutation copy number 與 clone frequency 共同決定 expected VAF；PCAWG 使用的簡化式也同時包含 `m`、`f`、`C` 與 `rho`。[PCAWG Nature paper](https://www.nature.com/articles/s41586-019-1907-7.pdf)（lines 1416–1424）
- PyClone 的原始模型同樣是以 Bayesian 方法估計 cellular prevalence，並處理 copy-number imbalance 與 normal-cell contamination。[PyClone](https://www.nature.com/articles/nmeth.2883)（abstract）

latent assignment / marginalized 是甚麼意思

--- 🤖 ASSISTANT [2026-09-01T13:29:26.251Z] ---
簡單說：

- **latent assignment**：隱藏的 SNV 歸屬。  
  例如某個 SNV 到底屬於 clone C1、C2 還是 C3，資料沒有直接告訴我們，所以用 `z_i` 表示這個未知變數。

- **marginalized**：不強行選一個答案，而是把所有可能性加權整合。

例如某 SNV 可能屬於：

```text
C1：30%
C2：50%
C3：20%
```

SMC 不會把 `z_i=C2` 存進 particle；它會計算：

```text
P(data | T, η)
= Σ_z P(data | T, η, z) × P(z | η)
```

因此：

```text
particle state = T + η
z = 被 likelihood 邊際化的隱藏 assignment
```

最後仍可從 posterior responsibility 產生「最可能 assignment」或 assignment uncertainty，但那是輸出結果，不是 SMC particle 的核心 state。

--- 🧑 USER [2026-09-01T13:30:37.453Z] ---
particle state 和 latent assignment的差異?

--- 🤖 ASSISTANT [2026-09-01T13:30:50.904Z] ---
兩者層級不同：

| 項目 | particle state | latent assignment |
|---|---|---|
| 意義 | SMC 用來代表一個候選解的內容 | 模型內部的未知變數 |
| 目前內容 | tree topology `T` + local fraction `η` | 每個 SNV 的 clone 歸屬 `z_i` |
| 粒度 | 一個 particle 一組 | 每個 SNV 各有一個 `z_i` |
| 目前處理 | 被 SMC 直接探索、更新、保存 | 對所有可能 clone 計算後邊際化 |
| 是否直接存在 particle | 是 | 否 |

例如一個 particle 可以是：

```text
T: C0 → C1、C0 → C2
η: C0=0.60, C1=0.30, C2=0.10
```

對某個 SNV，`z_i` 仍可能是：

```text
z_i=C0、C1 或 C2
```

模型會評估這三種可能，再加權整合，而不是把其中一個永久放進 particle。

所以目前的關係是：

```text
particle state: T + η
                  ↓
             推導 φ / CCF
                  ↓
    對每個 SNV 邊際化 z_i
                  ↓
       likelihood 與 assignment posterior
```

一句話：`particle state` 是 SMC 實際探索的候選解；`latent assignment` 是模型評估時存在、但目前被整合掉的隱藏變數。
