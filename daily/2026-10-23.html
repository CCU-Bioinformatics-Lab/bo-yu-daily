02CONIPHER 生成程式模擬了哪些 copy number 事件？完成

問題

做簡報時，使用者連續追問 CONIPHER 生成程式的細節：有沒有 mutation loss？WGD 是 gain 還是 loss？有沒有 LOH？coverage 每個 SNV 都一樣嗎？purity 怎麼分給 clone？算好的 VAF 真的有用來產生 read count 嗎？答案決定頁面怎麼畫，也決定 long read 版能沿用哪些步驟。

做法
  • 每題先讀 TRACERx_simulation_tool/src/ 的程式（evolution.py、sequencing.py、make_simulation.py），寫出行號。
  • 再數重跑的 150 份 No-Noise 資料（_events.tsv、_info.tsv），確認程式行為在資料裡真的出現。
  • 依使用者回饋，問「某工具模擬 X 嗎」時，先答「是／否」，而且指生成程式，不是建樹軟體。這條存進 memory。
結果
  • copy number 事件全都有（見表）。loss 只動媽媽那份；SNV 一律放在爸爸那份，所以一般版本的 SNV 不會因 loss 消失。
  • WGD 只有 gain：所選 clone 的每個位置，爸、媽、SNV 份數全部 ×2。clonal 放在 c1；subclonal 從 c1 以外隨機挑 1 個 subclone。
  • 先後：同一個 clone、同一個位置的事件隨機排先後；跨 clone 時祖先一定在前。這決定 multiplicity。
  • purity 分給 clone：用 Dirichlet(1,…,1) 隨機切給被選到的 clone，不看樹的結構。c1 的比例可以是 0，但 c1 的 CCF 永遠等於 purity。
  • read count：depth ~ Poisson(coverage × 該位置平均 copy number ÷ 全部位置平均)；alt ~ Binomial(depth, 期望 VAF)。coverage 每位病人一個值，各 SNV 的 depth 不同。
  • 生成程式用 Python 寫成，入口是 Jupyter notebook。
解讀

CONIPHER 生成器的 copy number 模型比 PhyClone 測試程式完整，可以當 long read 生成器的基礎。但它每個位置各自決定事件，沒有整段染色體的 segment；同一個 clone 裡 WGD 和各 SNV 的先後也是每個位置各自抽。要產生 HP 和同一條 read 上的 SNV 共現，必須先補 segment 結構（推論）。

還缺
  • 「沒有 segment」「WGD 先後各位置獨立」是讀程式的推論，沒有寫程式驗證。
  • 只數了 No-Noise 組；Noise 組的 mutation loss 只讀了程式。
  • CONIPHER 建樹工具是 R 寫的，這點出自記憶，本機沒驗證。
  • 這些查證結果只寫在簡報講稿與對話，沒有整理進 notes/05_OTHER_SIMULATORS.md。
