01C4 選錯樹，是 longbulksim 寫錯還是改良版 PhyClone 錯？是模型完成

問題

C4（read 上 SNV 共現的 pair term）在壓力測試樹上有兩種失效：模式 1 把一個 clone 拆成好幾個，模式 2 把 C3 推成第二個 root。早上的診斷顯示 pair term 太重，計畫是把它乘上權重 w < 1。下午出現一個更根本的疑問：選錯樹到底是 longbulksim 產生的資料錯了，還是改良版 PhyClone 錯了？

做法

依序做五件事，每一步都由上一步的結果決定：

  • 固定 w（0.5／0.3／0.2）掃描 36 個 run。
  • 真值樹 vs MAP 樹：129 個 run，把兩者的分數拆成 prior、SNV data likelihood、pair term，判定是抽樣沒找到還是模型偏好錯樹。
  • 模擬器解析期望檢查：不經過 PhyClone，直接檢查 90 個 sim 的輸出是否符合它自己的真值與宣稱機制，並注入 6 種錯誤確認檢查抓得到。
  • 把定序錯誤率 e 寫進 pair score（誤差模型），取代原本的固定容忍值 ε。
  • 再把「SNV 可能在另一條 HP」的不確定性放進 pair score。
結果
  • 錯在模型，不在模擬器。 90 個 sim、1097 項檢查全部通過，6 種注入錯誤全部被抓到。129 個 run 中只有 3 個是抽樣問題。
  • 模式 1 由 pair term 造成：b03 的錯誤樹在 pair term 上贏 20–71 log 單位。
  • 模式 2 主要由 FSCRP prior 造成：pair term 其實偏好真值，prior 偏好「一大一小」的 node 大小，把接近平手的情況推向錯的樹。
  • 固定 w 失敗。 模式 1 改善，但 C1／C2 分開的 run 從 9 降到 3–4，模式 2 變嚴重。
  • 誤差模型有效，但 e 必須從 normal 校正。 b03 用真實錯誤率 0.03 時模式 1 消失（clone 數 4／7／5 → 3／3／3）。e 高估時模式 2 回來。
  • HP 不確定性修好了它鎖定的 real s1，但整體沒有改善，正確的分支證據也被削弱。
解讀

三次「一律削弱 pair 證據」的修法結果一樣：錯的證據變弱，C4 對抗 prior、分開 C1／C2 的力量也一起變弱。所以 pair 證據的強度不要再調。採用誤差模型（e 從 normal 校正，HCC1395BL 是 0.004），HP 不確定性只留作選項 --pair-hp-uncertain。下一步改 FSCRP prior，計畫寫在 FSCRP_PRIOR_PLAN.md。

還缺

FSCRP prior 還沒改，只寫了計畫。real s1 剩下的錯誤樹（segment A 的 s8 放錯）是 base 模型的問題，還沒處理。全部結果只在壓力測試樹（3 seed × 4 種誤差）上，沒有在 TRACERx 隨機樹上重跑。解析期望檢查只證明模擬器照設計產生資料，不證明資料像真實 ONT。

02longbulksim 改成像 CONIPHER 一樣只填高階參數，並加入 ONT somatic caller 漏抓完成

問題

原本 longbulksim 要使用者自己寫 clones、segments、edges 的 YAML，使用者不會想填。另外它把每個真實 SNV 都當成 call 到，即使只有 1 條 alt read。真實流程中 somatic caller 會漏抓低 alt 數的 SNV，所以之前的結果可能太樂觀。

做法
  • 參考 CONIPHER 模擬器，加 longbulksim.generate：只填 clone 數、purity、depth 等高階參數，預設用 TRACERx 中位數。
  • 加 --preset tracerx／pcawg，WGD 改成依機率發生，clone 數沿用 TRACERx。
  • 用 CASTLE HCC1395 ONT（depth 中位 84×）上 ClairS 與 DeepSomatic 的實際 call，對照 SEQC2 真值 37,329 個位點，擬合「alt 數＋depth → 被 call 到的機率」曲線，接成 --caller clairs／deepsomatic。
結果
  • ClairS 大約要 ≥ 10 條 alt read，DeepSomatic 大約 ≥ 5 條。 alt 數相同時，depth 越高越難被 call 到，表示 caller 實際看的是 VAF。
  • 預設模擬（purity 0.41、50×）加上漏抓後：ClairS 只 call 到 72% truncal、17% subclonal SNV；DeepSomatic 是 92% 與 45%。
  • CCF < 0.2 的 subclone 幾乎都看不見（只有 purity 0.7＋DeepSomatic 例外）。
解讀

之前「可偵測 clone」用 alt ≥ 3 判定，比 ClairS 的實際門檻寬鬆很多，所以 10-25 的隨機樹 baseline 偏樂觀。低 purity 時 SNV 本來就少，會直接影響能推出幾個 clone。--caller 曲線只用 HCC1395 一個樣本擬合，所以預設仍是 none。

還缺

偵測曲線只來自一個細胞株（HCC1395，purity 約 1）；低 purity 的驗證找不到現成的 ONT call，沒有完成。preset 的 WGD 與 clone 數分布沒有對其他 cohort 交叉驗證。

03pair SNV 改成建樹後再挑樹，會比放進模型好嗎？不會完成

問題

pair SNV 要不要改成像 Sakamoto 2022 肺癌研究那樣，先用一般 PhyClone 建樹，再用 pair 證據挑樹，而不是把它放進模型？

做法

在 12 個 sim 上補跑沒有 C4 的 base 與 A2，再用兩種方式事後挑樹：軟（每棵樹乘上 C4 分數重新加權）與硬（照肺癌研究的條數門檻，只留違反最少的樹）。之後量 pair term 和 base 分數各自的變動幅度，並數一條 read 被算進幾個 pair。

結果
  • 事後挑樹比放進模型差。 base＋事後挑樹選錯 4–5／12 次，base＋C4 是 0／12；24 個 run 都推不出完整的 4 clone 樹。
  • 事後挑樹的有效樣本數只有 1–18，接近一個點估計。
  • pair term 太重。 它的變動是 base log_p 的 6.8–33 倍（中位數 11.6）。一條 read 平均被計入約 3.2 個 pair，最多 105 個。一個鹼基讀錯可以在同一條 read 的 9 個 pair 各罰一次，合計約 41 log 單位。
解讀

C4 仍然放在模型裡。事後硬篩選只當報告用的檢查，列出 MAP 樹違反哪些 pair。pair term 太重的診斷導出了下午 composite weight 的計畫（結果見第一項：失敗）。

還缺

事後挑樹只用現有的 1100 iteration 樣本；用更多 chain 讓 base 抽到 pair 支持的樹，結果可能不同，沒有測。

04longbulksim 的模擬資料像真實 HCC1395 ONT 嗎？4 項不像，修好其中 2 項完成

問題

longbulksim 產生的資料，在「沒有拿來當輸入參數」的統計量上，像不像真實的 long read bulk 資料？如果不像，C4 與 A1／A2 的結果可能被高估或低估。

做法

用 HCC1395 的真實 SNV 位置與 ASCAT CN 模擬一份 t50_n00，和真實資料用同一套統計定義比較（posterior predictive check）。發現不吻合後：

  • 用真實 phased het SNP 位置加上 longphase-s 的 tag 規則（het map），取代每條 read 獨立抽 tag。
  • 用 HCC1395BL normal 每 10 kb 的 read 起點密度（depth map）重現位置相關的 depth 起伏。
結果
  • 吻合：跨越 read 數 vs 間距、HP 深度 vs CN、split-HP 比例（模擬 2.1–2.2%，真實 2.4%）。
  • 原本 4 項不吻合：depth 起伏太小、tag 比例的位點差異太小、< 1 kb 的 SNV 同 HP 比例偏低（真實 0.82，模擬 0.58–0.65；推論是 APOBEC kataegis）、近距離 pair 共現偏少。
  • het map 修好 tag 比例，沒有擬合任何參數。
  • depth map 補回技術性的 depth 起伏：VMR 從 1.0 升到 1.81–2.46（真實 2.39–3.24）。剩下的差距推論來自 CN 估計誤差，本次不模擬。
解讀

原本模擬給每個位點的 HP 資訊太均勻、太完整，A1／A2 的增益可能被高估；近距離共現偏少，C4 拿到的證據可能偏少。het map 與 depth map 只用 HCC1395 校正，參數模式的人工座標配 depth map 會有 12–26% 的 SNV depth 為 0，所以兩者維持選填，不設為預設。

還缺

kataegis（成簇突變在同一條 haplotype）沒有放進模擬。PS block 方向與位點相關的錯誤長尾沒有建模。CN 造成的 depth 起伏沒有模擬。全部只對 HCC1395 一個細胞株比較。
