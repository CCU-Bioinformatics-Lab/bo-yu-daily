01真實 ONT 的 alt 計數比 binomial 分散多少？s 約 140完成

問題

longbulksim 用 binomial 抽 alt read 數，沒有額外雜訊。PhyClone（和 haploclone）用 beta-binomial，預設 precision 400。真實 ONT 資料的雜訊比這兩者大還是小？模擬資料會不會太乾淨，讓評估結果偏樂觀？

做法
  • 用 HCC1395BL normal 的 phased germline het（約 203 萬個位點，depth 中位 26），以 MLE 估 beta-binomial 的 μ 與 s，參數化和 PhyClone 相同。
  • 只用 AF 在 [0.2, 0.8] 視窗內的位點，並在 likelihood 裡扣掉視窗外的機率，避免 caller 的 AF 篩選造成偏差。
  • 用同樣 depth 的純 binomial 資料當對照，確認方法不會自己生出分散。
  • 依結果在 longbulksim 加選用參數 --allelic-precision，預設 0（維持 binomial），再把 10-27 的改動和這個功能分成兩個 commit。
結果
  • s = 141（依 depth 分三層：97／144／164）；binomial 對照組估出 s > 10,000，所以分散是真的。
  • ref bias 很小：μ = 0.49–0.50。
  • 換成「變異數是 binomial 的幾倍」：depth 50 時，longbulksim 1.0、PhyClone 預設 1.12、真實 1.35。
  • v0.8 開啟 s = 140 後，5 次模擬、2,135 個 SNV 估回 s = 137；關閉時輸出和 v0.7 逐位相同。67 個測試通過。
解讀

雜訊大小依序是 longbulksim 預設 < PhyClone 假設 < 真實資料。所以預設模擬會讓方法看起來比實際好；PhyClone 用 400 跑真實資料時低估雜訊，可能拆出假 clone。v0.8 讓之後的評估可以選擇用接近真實的雜訊。

還缺

只量了 normal 的 germline het，depth 約 26；tumor 的 somatic SNV 雜訊還沒量，這是下限。s 隨 depth 上升，換算到 depth 50 可能高估了放大倍數。PhyClone precision 400 vs 140 的敏感度測試還沒做。功能預設關閉，既有實驗都還是 binomial。

02read 共現能幫忙分兄弟 clone 嗎？要看 truncal 比例完成

問題

簡報說 longbulksim 會輸出「SNV 共現」。這些 pair 實際上落在樹上的哪種關係？兄弟 clone 之間（C4 最需要的證據）有多少？模擬的 pair 數量和真實資料比起來合不合理？

做法
  • 用預設參數跑 20 次模擬，每列 pair 依真值分成同一 clone、祖先→後代、不同分支，檢查對應的共現規則是否成立；不成立時查 genome 能否用 copy 結構解釋。
  • 用 SEQC2 HCC1395 真值比較每個 SNV 在 1–50 kb 內的鄰居數，看模擬是否偏少。
  • 依結果分別提高 SNV 密度（15.9、30/Mb）和降低 truncal 比例（0.5），各重跑 20 次。
  • 最後用 SEQC2 的 VAF 與 ASCAT CN 算真實 HCC1395 的 CCF，估 truncal 比例，再用這個比例模擬一次。
結果
  • 預設下 pair 幾乎都和 trunk 有關：trunk–trunk 81.9%、trunk–subclone 17.3%；兄弟 pair 只有 4 列。
  • 規則不成立的列 100% 能用 copy 結構解釋（同一 clone 61% 成立、祖先→後代 85%、兄弟 100%）。
  • 模擬的近距離鄰居只有真實的 1/4–1/2（1 kb 內 4.0×、50 kb 內 2.1×），原因是密度偏低、segment 邊界、kataegis 成簇。
  • 密度提高到 30/Mb：兄弟 pair 只從 4 變 6。truncal 降到 0.5：變 161。
  • HCC1395 約 75% truncal（CN 1+1 位點 75.1%，全部 74.6%），CCF 分布雙峰。truncal 0.75 模擬：兄弟 pair 41 列，10/10 棵分支樹都有，read 數中位 9。
解讀

共現能不能分兄弟 clone，主要取決於腫瘤有多少 subclonal SNV，不是 SNV 密度。TRACERx 典型肺癌幾乎沒有這種證據；HCC1395 有，但每棵分支樹約 4 列，不多。判讀共現時要考慮 copy 數：有 WGD 或單一 HP gain 時，同 clone 的兩個 SNV 不一起出現是正常的。

還缺

SEQC2 HighConf 偏向排除低 VAF 的 subclonal SNV，75% 可能高估。CN 與 VAF 來自 Illumina 批次，不是本機 ONT 批次。模擬沒有成簇模型，真實的兄弟 pair 應該更多（推論）。PhyClone 加不加 C4 在 truncal 0.75 下的建樹比較還沒做。預設密度是否改成 15.9 還沒決定。

03longbulksim 和 CONIPHER 的模擬差在哪？VAF 公式相同，但 CONIPHER 產生不了多分叉的樹完成

問題

使用者重新確認 CONIPHER 模擬器怎麼算預期 VAF，接著要知道 longbulksim 和它在 VAF、segment、座標、輸入參數、樹形、read 特徵上各差在哪，以及 longbulksim 的樹是否涵蓋所有 clone 組合。

做法
  • 對照兩邊原始碼（CONIPHER topology.py、evolution.py、conversion.py；longbulksim param_tree.py、sample.py、simulate.py）。
  • 樹形問題用實測回答：每種 clone 數 n = 3–6 各抽 20,000 棵樹，數出現幾種樹形和直線比例。
  • 拿一列模擬 SNV 畫成 PNG（輸入欄位、真值、依 HP 拆開的 read、預期 VAF 計算），再用它檢查反推的 CCF。
結果
  • VAF：兩邊都是「突變 copy 數 ÷ 總 copy 數」，normal 依 1 − purity 加權。CONIPHER 沒有 segment，輸出的 CHR／POS 是最後補的假座標（hg18 長度）。
  • 樹形：n = 6 時可能有 20 種樹形，CONIPHER 只出現 11 種、直線比例 0.04；longbulksim 20 種都出現、直線比例 0.63。
  • CCF：longbulksim 先定樹再用 Dirichlet 抽細胞比例，所以 parent ≥ children 總和自動成立，只篩 min_ccf／min_gap 0.05。
  • 單一 SNV 反推 CCF：0.705，真值 0.656 在 95% 區間 0.36–1.00 內；只看 HP2 的 read，觀察 VAF 0.23，較支持 multiplicity 1（預期 0.19）而非 2（0.38）。
解讀

單一樣本最難的是分直線樹和分支樹，所以兩者比例要接近真實。CONIPHER 的「先二分再剪枝」在 clone 多時幾乎只產生分支樹，longbulksim 的做法較適合我們的評估。longbulksim 不會漏掉任何樹形，但各樹形的機率不相等，不能當暴力列舉用。使用者決定：建樹軟體不看座標，真實 GRCh38 座標先不做。

還缺

p_linear 對所有 clone 數用同一個值，TRACERx 的直線比例可能隨 clone 數下降，還沒分層校正。分支樹內部（多分叉比例）沒有和真實資料對照。PNG 與樹形腳本只存在 session 暫存區，沒有進 lab_report/。
