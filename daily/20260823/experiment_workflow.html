第二站：先小跑，再正式跑

每一階段都像不同難度的試跑。前面失敗，就不浪費時間跑後面的設定。

1

Smoke

先看機器能不能正確讀資料。

  • 20 sites
  • 16 eligible
  • 2 chains

不判定收斂或生物學答案

2

Pilot

比較不同 K 與 chains 的行為。

  • K = 4 / 6 / 8
  • 每個 K：4 chains
  • 300 iterations

R-hat ≤ 1.10 只是試跑訊號

3

Formal main

主分析固定條件。

  • K = 6
  • rho = 0.99
  • 4 chains
  • 1500 / 1000 burn-in

三種 grouped holdout

4

Sensitivity

主設定通過後才檢查穩定性。

  • K = 4 / 8
  • rho = 0.97 / 0.95

不是新的 ASCAT purity

第三站：把一部分資料暫時藏起來

Holdout 就像考試：先不讓模型看某一群 SNV，最後檢查它能不能預測回來。

PS grouped

同一 phase block 不拆開。沒有 PS 的 SNV 退回 singleton。

Chromosome grouped

整條 chromosome 當作一組，檢查跨染色體的預測表現。

ASCAT segment grouped

以 CN segment 分組，檢查 copy-number context 改變時是否仍穩定。

重要邊界Holdout 是 workflow 的評估控制，不是新的 biological parameter；PS 也不會因此進入 topology likelihood。

第四站：結果要通過哪些檢查？

「程式跑完」和「結果值得繼續看」是兩件事。

✓

資料正確

schema、counts、CN、purity 與 eligibility 都通過。

✓

鏈彼此一致

用 CCF/phi ranks 看 R-hat 與 ESS。

✓

樹與分配穩定

看 edge support 與 SNV assignment agreement。

✓

能預測藏起來的資料

看 holdout coverage 與 predictive log score。

還沒有自動完成的事完整 prior/posterior predictive、C++ sampler restore、candidate SMC diagnostics、CNA event 到 tree node 的證明，以及 single-cell lineage validation，現在都不能假設已由 wrapper 完成。

出錯時，怎麼知道是哪一站？

每一站都寫入 trace。先看失敗階段，再看該階段的檔案。

1status.json：先找 failed_stage / failed_scope
2execution_trace.jsonl：看最後一個失敗事件
3workflow_error.log：看完整錯誤與 traceback
4_FAILED：這次 run 不得當成研究結果

Resume 的白話版

已完成的 cell 可以重新讀取完整 artifacts。中途壞掉的 C++ chain 目前不能從 checkpoint 接著跑；要修正問題後建立新的 run。
