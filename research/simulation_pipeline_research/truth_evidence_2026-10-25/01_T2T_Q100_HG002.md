# T2T-Q100（HG002 Q100 diploid assembly）作為「HP 層」真值證據

> 調查日期：2026-10-25。範圍：只查 T2T-Q100／HG002。
> 證據等級：〔官方文件〕＝官方網站、GitHub README、FTP／S3 index、檔案 header；〔論文〕＝期刊或 preprint；〔程式實作〕＝pipeline 原始碼；〔推論〕＝本文推論或自行由小檔計算。

## 1. 結論

1. **Q100 已正式發表。** Hansen et al., *Cell* 2026（DOI 10.1016/j.cell.2026.06.016），preprint 是 bioRxiv 2025.09.21.677443。它宣稱 99.4% 的 diploid HG002 genome 沒有可偵測錯誤。〔論文〕
2. **目前最新版是 hg002v1.2（2026-08-06）。** benchmark 論文與 GIAB v5.0q 都用 **v1.1**。v1.1 的 Merqury QV 是 Q68.9（31-mer），21-mer 是 Q76.2。〔官方文件〕〔論文〕
3. **兩條 haplotype 以 contig 名稱標示。** 例如 `chr1_MATERNAL`、`chr1_PATERNAL`。parental 歸屬來自 Verkko 組裝時用的 **父母 Illumina reads（HG003／HG004）**。〔官方文件〕〔論文〕
4. **GIAB v5.0q 是第一個以 Q100 v1.1 為基礎的全基因組 benchmark。** GRCh38 small variant 區域是 2,739,407,815 bp，SV 區域是 2,756,244,708 bp。VCF 是 **fully phased** 的 `GT`（例如 `1|0`）。〔官方文件〕
5. **v5.0q 的 phased GT 順序是 `PAT|MAT`。** defrabb 把 paternal 當 hap1、maternal 當 hap2 傳給 dipcall。這是程式碼層級證據，使用前要再驗證一次。〔程式實作〕
6. **ONT HG002 有現成 GRCh38 haplotagged CRAM。** ONT `giab_2025.01`：R10.4.1、Dorado SUP v5.0.0、約 47×、reference 與使用者相同（`GRCh38_no_alt_analysis_set`）。每片 flowcell 約 90–99 GB。〔官方文件〕
7. **ONT 實際 phase block 長度可直接量。** 由 `giab_2025.01` 的 `haploblocks.gtf`（Clair3 + WhatsHap，約 43–47×）自算：block N50 約 1.50–1.59 Mb，約 4,600–4,800 個 block。〔推論〕
8. **Q100 能證明 germline phasing 層，不能證明 tumor clone 層。** HG002 是正常 lymphoblastoid cell line。它沒有 somatic CNA，也沒有 clone tree。用 HG002 做 spike-in 的公開完整流程未查到；只有零件（BAMSurgeon、樣本混合、GIAB mosaic set）。〔推論〕

## 3. 各問題詳細

### Q1. Q100 assembly 本體

- **論文。** Hansen NF, Dwarshuis N, Ji HJ, … Koren S, Zook JM, Phillippy AM. "A complete diploid human genome benchmark for personalized genomics." *Cell* 189(16):4857–4875.e31, 2026-08-06。DOI 10.1016/j.cell.2026.06.016。preprint：bioRxiv 2025-09-21，DOI 10.1101/2025.09.21.677443。〔論文〕
- **涵蓋。** 新增 701.4 Mb autosomal 序列與兩條性染色體（216.8 Mb），共約 15.3% 的 genome 是以往 benchmark 沒有的。〔論文〕
- **準確度。**
  - 99.35% 的 diploid genome 長度沒有可偵測錯誤（v1.1）。〔論文，PMC12458380〕
  - Merqury QV（31-mer）：v0.7 是 Q63.1，v1.1 是 Q68.9。21-mer 是 Q76.2。〔論文〕
  - low-confidence 區域：3,172 個，共 38.8 Mb（0.65%）。〔論文〕
  - GitHub 版本表（另一套 k-mer 計算）：v0.9 是 QV 71.8，v1.0 是 75.1，v1.1 是 77.8；v1.2 段落把 v1.1 寫成 68.9、v1.2 寫成 69.2。兩組數字的 k-mer 資料庫不同，原文沒有說明。〔官方文件，https://github.com/marbl/hg002〕
- **版本。**
  - v1.0：2023-10-31。v1.0.1：只把 3 個 ambiguity code 換成 A/C/G/T，座標不變。v1.1：2024-07-22，修 4,013 個錯誤。v1.2：2026-08-06，修補 612 個區域，是目前最新版。〔官方文件〕
  - v1.1 GenBank：paternal GCA_018852605.3，maternal GCA_018852615.3（BioProject PRJNA730823）。〔官方文件〕〔論文〕
- **MAT/PAT 命名。** v1.1 contig 名稱是 `chr1_MATERNAL`、`chr1_PATERNAL` 等（由 `hg002v1.1.fasta.gz.fai` 確認）。另有 `.mat.fasta.gz`、`.pat.fasta.gz` 分檔，以及 `mat_Y_EBV_MT`、`pat_X_EBV_MT` 等含性染色體的組合檔。〔官方文件〕
- **parental 怎麼定。**
  - 初始組裝用 Verkko。它用 HG002 父母（HG003、HG004）的 Illumina reads 做 phasing；Strand-seq 和 Hi-C 用於跨 rDNA array 的 scaffolding。〔論文〕
  - 父母 Illumina 31-mer 標出 794 個可能的 haplotype switch error（共 31.6 kb）。〔論文〕
  - GitHub 版本說明只寫 Verkko，沒有寫 hifiasm。〔官方文件〕
  - Verkko trio mode 的細部參數在 Supplementary，本次未讀到。〔未查到〕

### Q2. 以 Q100 為基礎的 benchmark

- **GIAB v5.0q。** 以 Q100 v1.1 為基礎。提供 GRCh37、GRCh38、CHM13v2.0 三種座標。分 small variant（smvar）與 structural variant（stvar）兩組 VCF+BED。〔官方文件，v5.0q README〕
- **產生方式。** defrabb pipeline 呼叫 dipcall v0.3（minimap2 `-z200000,10000`）。起點是每條 haplotype 與 reference 1:1 對齊的區域。接著排除：assembly gap 及其 flank、有 alignment break 的大 repeat（satellite、>10 kb tandem repeat、segdup）、inversion、SV 影響區（smvar 才排除）、dipcall bug、PAV 與 dipcall 不一致處、Q100 已知錯誤、mosaic variant。〔官方文件〕
- **涵蓋 genome 多少。**
  - GRCh38 smvar：dipcall diploid 區域 2,840,444,036 bp，排除後 2,739,407,815 bp。〔官方文件，`HG002_GRCh38_v5.0q_smvar.exclusion_stats.txt`〕
  - GRCh38 stvar：2,756,244,708 bp。〔官方文件〕
  - 換算約為 GRCh38 primary 總長（3.10 Gb，含 N）的 88%。〔推論〕
  - README 指出：因為排除 inversion 內部，有些 v4.2.1 涵蓋的區域在 v5.0q 反而被排除。〔官方文件〕
- **phasing truth 怎麼取得。**
  - v5.0q VCF 的 GT 是 phased（例如 `1|1`、`1|0`），FORMAT 只有 `GT:AD`。phase 直接來自 assembly 的 haplotype，所以整條染色體是同一個 phase（chromosome-scale）。〔官方文件，由 VCF header 前 200 KB 串流確認〕
  - GT 順序：defrabb `rules/asm-varcall.smk` 寫 `h1 = paternal.fa`、`h2 = maternal.fa`，再呼叫 `run-dipcall … h1 h2`。dipcall README 範例也是 `pat.fa.gz mat.fa.gz`。所以 **左 allele = PAT，右 allele = MAT**。〔程式實作，https://github.com/usnistgov/defrabb、https://github.com/lh3/dipcall〕
  - 注意：這是依目前 defrabb master 推得。使用前請用 chrX non-PAR（男性，X 來自母親）或 hapmer 驗證一次。〔推論〕
- **相關 draft 版本。** v0.011–v0.020 的 draft benchmark 在 https://ftp-trace.ncbi.nlm.nih.gov/ReferenceSamples/giab/data/AshkenazimTrio/analysis/ 下（例如 `NIST_HG002_DraftBenchmark_defrabbV0.019-20241113/`）。v5.0q 對應 defrabb v0.020（2025-01-17）。〔官方文件〕
- **第三方用法。** Illumina DRAGEN 4.5 文件以 `T2TQ100-v1.1-v0.019` truth set 報 HG002 準確度。〔官方文件，Illumina DRAGEN 文件〕

### Q3. 怎麼用 Q100 評估 phasing

**標準做法（建議依序）：**

1. **VCF 層 phasing 比較：`whatshap compare`。**
   - truth：v5.0q smvar VCF（`PAT|MAT`），限制在 benchmark BED 內。query：longphase 輸出的 phased VCF。
   - 只比兩邊都是 het 的 SNV。
   - switch error：一個檔案的 haplotype 原本對應另一檔的某條，之後改為對應另一條，算一次 switch。兩個連續 switch 算一次 flip。關係式：`nonflip_switches + 2 * flips = all_switches`。〔官方文件，WhatsHap docs〕
   - Hamming distance：與 truth haplotype 不同的位點數；工具會取較小的那一邊。〔官方文件〕
   - 報告分 `blockwise_*`（所有交集 block）與 `largestblock_*`（最大 block）。〔官方文件〕
2. **block 長度：`whatshap stats`。** 它的 "N50" 實際是 NG50（以 VCF header 的 contig 長度為分母）。`--block-list` 輸出每個 PS block 的 start/end/variant 數。〔官方文件〕
3. **HP1/HP2 對到 MAT/PAT。**
   - longphase 的 HP1/HP2 只在同一個 PS block 內有意義。〔推論〕
   - 每個 PS block 內，數 query GT 與 truth GT 一致的 het SNV 比例。多數一致就把 HP1 定為 PAT，否則定為 MAT。這等於 Hamming 的 block 內最小化。〔推論〕
4. **read 層級 haplotag 正確率。** 有兩條路：
   - (a) 把 reads 另外對齊到 `hg002v1.1.fasta.gz`（diploid，MAT+PAT 同時放）。read 的 primary alignment 落在 `_MATERNAL` 或 `_PATERNAL` 就是它的真值。ONT `gm24385_2023.12` 與 `londoncalling2024` 已有這種現成 BAM（對 hg002v1／v1.0.1）。〔官方文件〕
   - (b) 用 hapmer：GQC 用 FASTK 的 40-mer（只出現在其中一條 haplotype）判斷 phasing。〔官方文件，https://gqc.readthedocs.io〕Elbers et al. 2024（bioRxiv 10.1101/2024.10.18.619002）用 readmer／hapmer 量 ONT read 的 phase switching。〔論文〕
   - 然後把 longphase haplotag 的 HP tag 與真值比較，得到 read-level 正確率與 unphased read 比例。〔推論〕
5. **assembly 層：GQC。** Q100 論文開發的 Genome Quality Checker（https://github.com/marbl/GQC）。它用 haplotype-aware alignment 加 two-state HMM 判斷 phase block 與 switch。`readbench` 子命令可報告 read set 與 benchmark 的差異。〔論文〕〔官方文件〕
6. **其他比較工具（v5.0q README 推薦）。** small variant：`hap.py --engine vcfeval --gender male`，配 GIAB v3.6 stratification。SV：`truvari bench --refine`、hap-eval、vcfdist、aardvark。〔官方文件〕
7. **hapdiff。** 它是 diploid assembly 的 SV caller（輸入 ref、pat、mat），輸出 phased SV VCF 和 confident BED。它不是 phasing 評估工具。〔官方文件，https://github.com/KolmogorovLab/hapdiff〕

**實際數字：**

- **LongPhase 原論文。** Lin JH, Chen LC, Yu SC, Huang YT. *Bioinformatics* 38(7):1816–1822, 2022。DOI 10.1093/bioinformatics/btac058。SNP+SV co-phasing 的 block N50 = 25 Mbp，現有方法是 10–15 Mbp。ONT ultra-long 每個染色體臂 1–26 個 block。〔論文〕這篇早於 Q100 v1.x，truth 不是 Q100。〔推論〕
- **ONT 現成 phasing 的 block N50。** 由 `giab_2025.01` SUP `haploblocks.gtf` 自算（Clair3 + WhatsHap，非 longphase）：〔推論〕
  - PAW70337（46.8×）：4,816 個 block，總長 2.48 Gb，N50 = 1.50 Mb。
  - PAW71238（43.0×）：4,626 個 block，總長 2.49 Gb，N50 = 1.59 Mb。
- **Q100 論文本身。** 它說含 ONT 的 assembly 有最好的 phase switch 表現（因 read 較長）。可見內文沒有 variant call set 的 switch error 數字；細節在 Supplementary。〔論文〕
- **ONT 臨床基因 phasing 評估。** Damaraju et al. 2024（ONT resource centre）。用 HG002、GIAB VCF 與 Q100 assembly 衍生 VCF，Clair3 + WhatsHap。結論：對齊 CHM13 比 GRCh38 的 phasing 錯誤少。頁面沒有數字。〔官方文件〕
- **用 Q100 評 longphase 的 switch error 數字：未查到。**

### Q5. 用 HG002 做 spike-in／in silico tumor

- **完整流程（Q100 haplotype 植入突變 → 模擬 read → 建 clone tree）：未查到公開工具或論文。**
- 可用的零件與先例：
  - **BAMSurgeon**（Ewing et al., *Nat Methods* 2015，DOI 10.1038/nmeth.3407）。把 SNV／indel／SV 植入真實 alignment，產生 synthetic tumor 與 truth VCF。用於 ICGC-TCGA DREAM challenge。〔論文〕README 沒有提到 haplotype／long read 支援。〔官方文件〕
  - **BAMSurgeon 多 subclone 模擬**：PLOS ONE 2018（DOI 10.1371/journal.pone.0202982）在 NA12878 上植入 somatic SNV／indel，改變 subclone 數、VAF、突變密度。是短讀資料。〔論文〕
  - **ClairS／ClairS-TO 的樣本混合法。** 把兩個 GIAB 樣本（例如 HG001 + HG002）的真實 reads 混合。只在其中一個樣本出現的 germline variant 當作「somatic」。ClairS v0.1.5 用 HG001/HG002、HG003/HG004 pair 訓練 ONT Dorado 5 kHz model。〔官方文件，https://github.com/HKU-BAL/ClairS〕〔論文，ClairS-TO：DOI 10.1038/s41467-025-64547-z〕
  - **ClairS 的真實樣本訓練** 用的 HCC1937、HCC1954、H1437、H2009 來自 Park et al.（bioRxiv 10.1101/2024.08.16.608331）。這些與本專案的細胞株相同。〔官方文件〕
  - **Severus**（Keskus et al., *Nat Biotechnol* 2025，DOI 10.1038/s41587-025-02618-8）。HG002 只用於 germline SV benchmark（配 hapdiff）。synthetic tumor 用 CHM1 + CHM13 HiFi reads 混合，不是 HG002。〔論文〕
  - **GIAB HG002 mosaic benchmark**（Daniels et al., *Cell Genomics* 2025，DOI 10.1016/j.xgen.2025.101104）。85 個真實 subclonal SNV，VAF 5–30%，2.45 Gbp 區域。可當低 VAF 真值，但數量很少。〔論文〕
  - **LongPhase-S**（Ho, Zheng, Luo, Chiang, Huang；bioRxiv 2025-11-20，DOI 10.1101/2025.11.20.689492）。做 purity estimation 與 somatic haplotyping。摘要提到 6 株 cancer cell line、8 個 dataset。是否使用 HG002 synthetic tumor：未查到（全文 PDF 超過抓取上限）。〔論文〕
  - **專案範圍規則**：clonesim、VISOR、PSiTE 已依專案規則排除，本文不列為候選。〔推論〕
- **可行的自建路線（未驗證）。** 〔推論〕
  1. 以 v5.0q phased VCF 定 PAT/MAT 的 germline het SNP。
  2. 從 `giab_2025.01` SUP CRAM 取 reads，每條 read 依 diploid alignment 或 haplotag 得到真 haplotype。
  3. 依 HP-aware 真值樹，在指定 haplotype 的 reads 上植入 SNV（BAMSurgeon 類邏輯），並依 clone CN 做 haplotype-specific 的 read 抽樣（gain = 加抽，deletion／LOH = 移除該 haplotype reads）。
  4. 這樣 ONT 錯誤模式、read 長度、PS block 斷點都來自真實資料，只有 somatic 層是模擬的。

### Q6. 限制

- HG002 是正常男性 lymphoblastoid cell line（GM24385）。它沒有 somatic CNA、沒有 clone 結構，也沒有 tumor purity。〔推論〕
- 有極少量真實 mosaic SNV（85 個，VAF 5–30%），不是 clone tree。〔論文〕
- 腫瘤的 LOH／cnLOH 會讓 germline het SNP 變成 hom，PS block 會斷在 LOH 區。HG002 沒有這個現象，所以不能驗證「LOH 區的 phasing 行為」。〔推論〕
- v5.0q 排除 segdup break、inversion、satellite 等區域。這些區域的 phasing 真值不能直接用。〔官方文件〕
- `giab_2025.01` 的 phasing 是 WhatsHap，不是 longphase。要比 longphase，需要自己在 CRAM 上重跑。〔官方文件〕〔推論〕
- ONT basecaller 版本不同：HG002 是 Dorado SUP v5.0.0；使用者的 H1437／H2009 是 Guppy SUP（見 `tumor_sample.md`）。錯誤模式比較要分開說明。〔官方文件〕〔推論〕

## 4. 對使用者模擬的「可以證明／不能證明」對照表

| 模擬的 HP 層元件 | Q100 能否證明 | 用什麼資料／方法 | 說明 |
|---|---|---|---|
| germline het SNP 密度與位置 | **可以** | v5.0q smvar VCF + BED | 直接數每 Mb 的 het SNV 數，與模擬參數比。〔推論〕 |
| PS block 長度分佈 | **可以** | 在 `giab_2025.01` CRAM 跑 longphase；`whatshap stats --block-list` | 現成 WhatsHap block N50 約 1.5 Mb 可當第一個參照。〔推論〕 |
| PS block 邊界位置（het 稀疏、repeat） | **可以（部分）** | 同上，配 GIAB v3.6 stratification | 只限 benchmark BED 內。〔推論〕 |
| switch error 率 | **可以** | `whatshap compare` 對 v5.0q（`PAT|MAT`） | 得到真實 ONT + longphase 的 switch／flip 率。〔推論〕 |
| Hamming error | **可以** | 同上 | 〔推論〕 |
| unphased read 比例 | **可以** | longphase haplotag 結果；真值用 diploid alignment 或 hapmer | 〔推論〕 |
| read 的 haplotag 錯誤率 | **可以** | reads 對齊 `hg002v1.1.fasta.gz` 或 GQC `readbench` | 〔推論〕 |
| ONT 錯誤模式（indel、homopolymer、QV 校正） | **可以** | GQC `readbench`；Q100 論文指出 long read QV>20 時實際準確度低於標示 | 〔論文〕〔推論〕 |
| 同一 read 上多個 SNV 的共現 | **可以（germline 部分）** | 真實 read 上 germline het SNP 的共現 | somatic SNV 共現仍需模擬。〔推論〕 |
| SNV 的 HP1/HP2 歸屬（somatic） | **不能直接** | 只能用 spike-in 自建 | HG002 沒有 somatic SNV。〔推論〕 |
| haplotype-specific gain | **不能** | — | HG002 無 somatic CNA。〔推論〕 |
| HP2 deletion 造成突變遺失 | **不能** | — | 〔推論〕 |
| cnLOH | **不能** | — | 也無法驗證 LOH 區的 PS block 斷裂。〔推論〕 |
| clone tree topology、CCF、purity | **不能** | — | 需要腫瘤真值（例如 HCC1395 golden tree 或 single-cell）。〔推論〕 |
