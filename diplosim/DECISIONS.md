# diplosim 決策紀錄

| 日期 | 決策 | 理由 | 證據／可逆性 |
|---|---|---|---|
| 2026-10-29 | 用 Rust 重新實作，照 CONIPHER 的步驟一步一步移植 | 使用者決定。前一版模擬器一次改了 CONIPHER 11 步中的 10 步，看不出每個改動來自哪個需求 | 對照：`docs/conipher_steps.md` |
| 2026-10-29 | 不加入 `het_map`、`depth_map`、`caller`、`allelic_precision` | 使用者決定。這四個都只用單一資料集校正（HCC1395／HCC1395BL） | 可逆：之後要加，再逐一提出 |
| 2026-10-29 | 固定只有一個 bulk sample（不提供 CONIPHER 的 `n_samples`） | 使用者決定。病人定序成本高，實務上不可能隔一段時間重複定序，也不可能分別定序多個腫瘤區域。和 2026-10-25 老師指示的研究主軸（單一 bulk 樣本）一致 | 多 sample 只當上限參考，不做預設。連帶影響的 `min／max_clones_per_sample`、`all_leaf_observed` 怎麼處理，還沒決定（見 `docs/conipher_steps.md` S1） |
| 2026-10-29 | 不加入 `--preset` 與 `--phased`（`phased_fraction`） | 使用者決定。`--preset` 屬於 cohort 校正，和雙套體無關；`phased_fraction` 的 0.859 只來自 HCC1395 | 可逆。連帶影響待決：沒有 `phased_fraction`，HP tag 要怎麼決定（例如全部 read 都有 tag），還沒決定 |
| 2026-10-29 | clone 數與 SNV 數的參數名用 `n_clones`、`n_snv`，不用 CONIPHER 的 `n_nodes`、`n_positions` | 使用者決定。意思和 CONIPHER 相同：`n_clones` 是腫瘤 clone 數（不含 normal，`topology.py:64-71`），`n_snv` 是 SNV 數 | 只是改名；預設值還沒決定（CONIPHER 必填） |
| 2026-10-29 | 不加入 `min_clones_per_sample`、`max_clones_per_sample`、`all_leaf_observed` | 使用者決定，理由同 `n_samples`：只有一個 bulk sample。這三個參數只用來決定「每個 sample 放哪些 clone」（`sequencing.py:20-63`） | 結果：樹上所有 clone 都在這一個 sample 裡；不會有看不見的 clone |
| 2026-10-29 | 加入 `prop_truncal_snvs`（名稱照 CONIPHER） | 使用者決定。意思：全部 SNV 中放在 normal → trunk 這條邊的比例（`evolution.py:49-50`） | 預設值待決（CONIPHER 0.5）。其餘 SNV 怎麼分給 subclone（CONIPHER 每邊 ≥ 1）也待決（`minimum_branch_length`） |
| 2026-10-29 | 加入 `prop_pos_gained`、`prop_pos_lost`、`prop_gained_truncal`、`prop_lost_truncal`（名稱與意思照 CONIPHER） | 使用者決定。gain／loss 數 = 全部 SNV position × `prop_pos_gained`／`prop_pos_lost`；其中 truncal 的比例 = `prop_gained_truncal`／`prop_lost_truncal`（`evolution.py:213-246`） | 待決：預設值；單位用 position（CONIPHER）還是 bp（若 diplosim 有 segment）；subclonal loss 數會扣掉 mutation loss 數（`evolution.py:236`），mutation loss 的參數還沒決定 |
| 2026-10-29 | 已加入參數的預設值先照 CONIPHER `tx_simulation`：`prop_truncal_snvs` 0.5、`prop_pos_gained` 0.5、`prop_pos_lost` 0.3、`prop_gained_truncal` 1、`prop_lost_truncal` 1；`n_clones`、`n_snv` 和 CONIPHER 一樣必填。gain／loss 比例的單位先用 position | 使用者決定，暫定（「先」）。和原版一致，之後每個改動都有對照組 | 來源 `simulate.py:13-46`。可逆：TRACERx 中位數等其他值之後再決定 |
| 2026-10-29 | 加入 `gain_events`、`loss_events`，預設照 CONIPHER：`['gain_A', 'gain_B', 'gain_both']`、`['loss_B', 'cnloh_B']` | 使用者決定，暫定。每個 gain／loss position 從清單等機率挑一種（`evolution.py:191-194, 370-375`） | 待決：SNV 可以在 B 之後，`gain_B`／`loss_B` 會影響 SNV，「複製的一定是帶突變那份」的假設也要重想；`loss_A`、`cnloh_A` 仍只給 mutation loss 用 |
