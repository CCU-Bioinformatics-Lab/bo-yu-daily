02 · 模組責任

誰負責什麼，誰不能越界？

核心原則是「內部做法可以替換，但上下游 contract 與責任不能偷偷改變」。

data input
已實作

拿到不同來源的 reads、CN 和 purity，整理成 model 看得懂的一張張 SNV 小卡。

  • 拿到：reads、CN、purity 和檢查資料。
  • 交出去：每個 SNV 一行的整齊資料。
  • 另外留下：哪些 SNV 可以用、哪些被排除，以及原因。
不負責：posterior、VAF 公式、tree 搜尋、結果驗證。
model
baseline 可執行

拿到一張 SNV 小卡和一個候選答案，判斷「如果這個答案是真的，看到這些 reads 合不合理」。

  • 拿到：SNV 小卡和 inference 提出的候選樹／細胞比例。
  • 交出去：每個候選答案的合理程度。
  • 目前做法：用 reads、CN、purity 算一個預期比例，再和真實 reads 比較。
不負責：選 SMC/MCMC、resampling、結果呈現、claim 判定。
inference_algo
SMC 可執行

像一群人各自畫不同的腫瘤樹，再請 model 比較哪一張比較像資料。

  • 拿到：model 的判斷規則和整理好的 SNV 小卡。
  • 交出去：很多可能的腫瘤樹、每個 clone 的細胞比例和診斷紀錄。
  • 白話：答案太像時要重新找路，不能只卡在第一棵樹。
不負責：重新定義 model、發明 VAF、把候選樹宣稱成真理。
output
artifacts 可產生

拿到許多候選樹和分數，整理成研究者看得懂的樹、比例和 SNV 歸屬。

  • 拿到：inference 找到的候選樹和相關紀錄。
  • 交出去：誰是誰的 parent、每個 clone 有多少細胞、每個 SNV 放在哪個 clone。
  • 注意：這些仍可能只是候選答案，不是生物學真相。
不負責：重新推理、修改 likelihood、宣布 high-confidence。
validation
MVP 規格／scaffold，尚無獨立 runner

像獨立品管員，拿候選答案和檢查紀錄來問：「這個答案現在可以相信到什麼程度？」

  • 拿到：候選樹、重複執行結果和檢查紀錄。
  • 交出去：哪些地方穩定、哪些地方不穩，以及目前最多能說到哪裡。
  • 目前限制：獨立 validation runner 尚未完成。
不負責：修改上游、重跑 inference、把失敗結果變成功。
experiment_workflow
編排層

它不是另一個算答案的模組，而是工廠經理：安排每一站何時跑、留下什麼紀錄、哪一站失敗就停下來。

  • 拿到：設定、資料、各模組的交接規則。
  • 交出去：一份可追溯的執行紀錄，包含成功、失敗和停止原因。
  • 白話：_SUCCESS 只代表流程走完，不代表生物學答案正確。
不負責：定義 posterior、取代 inference、取代 validation 的科學判定。

03 · data input → model

一個簡單 SNV：資料最後怎麼交給 model？

先不要把它想成複雜的模型。data input 做的事情，就是把「我們在 reads 中看到什麼」整理成 model 可以逐列閱讀的小卡。

上游資料看到什麼？

SNVchr1:100:A>G
原本是 A，這個位置看到 G。
看到的 reads100 條 reads 中，70 條支持 A，30 條支持 G。
CNmajor = 2、minor = 1，合計 CN = 3。
purityrho_ASCAT = 0.99，估計樣本約 99% 是腫瘤細胞。
是否可用model_include = yes、model_status = eligible。

交給 model 的 SNV 小卡

mutation_id = chr1:100:A>G ref_reads = 70 alt_reads = 30 total_reads = 100 major_cn = 2 minor_cn = 1 total_cn = 3 rho_ASCAT = 0.99 model_include = yes model_status = eligible

白話：這一列只是在說「這個位置看到 70 個 A、30 個 G，CN 是 2+1，而且可以拿來分析」。它還沒有說這個 SNV 屬於哪個 clone。

model 接下來會問：如果這個 SNV 在 90%、50% 或 25% 的腫瘤細胞中，哪一種情況最能解釋「70 條 A、30 條 G」？所以 observed 30% G 是輸入資料，不是 model 直接採用的最終 clone fraction。

04 · 一個 SNV 的旅程

資料如何一路變成候選答案？

先看懂這條故事：我們先把 reads 中看到的內容交給 model；model 再替不同候選狀態預測「應該看到多少變異」；inference 最後比較哪一種候選最能解釋真實 reads。

1

讀入一張 SNV 小卡

例如 70 條正常 A、30 條變異 G，外加這個位置的 DNA 拷貝數和樣本 purity。

2

先問一個假設

假設這個 SNV 在某一群腫瘤細胞裡，模型先預測應該有多少 reads 會看到 G。

3

試很多種腫瘤樹

SMC 讓不同候選樹輪流接受同一個 model 檢查，看看哪一棵比較能解釋資料。

4

把結果翻成白話

整理成「誰是誰的 parent」、「每個 clone 大約占多少細胞」和「SNV 可能屬於誰」。

5

最後檢查能不能信

比較不同重跑、holdout 和診斷紀錄；不穩定就只能保留為候選答案。

目前程式怎麼判斷？

  1. 先看樣本中正常細胞與腫瘤細胞的大致比例。
  2. 再看這個位置有幾份 DNA 拷貝，以及候選 clone 占多少腫瘤細胞。
  3. 由這些資料估計「每一條 read 看到變異 G 的機會」。
  4. 最後問：如果每條 read 都依照這個機會出現，看到 70 個 A、30 個 G 合不合理？

目前程式用的是簡單的 Binomial read model；白話就是把每條 read 當成一次獨立觀察。

文件中的未來版本

未來的 PhyClone-compatible 版本，會把三種來源分開看：

  1. 正常細胞。
  2. 腫瘤細胞中沒有這個變異的部分。
  3. 腫瘤細胞中帶有這個變異的部分。

再把所有合理的 DNA 配置一起計算，不先硬選唯一答案。這個「預期會看到多少變異」的比例在文件中叫 PhyClone xi。

error_rate = 0.001 代表文件預留的定序錯誤下限；目前尚未接上 Python、C++、config 或 tests。

06 · 事實階梯

哪些事情已經能說？哪些還不能？

目前可確認
  • v4 canonical input builder。
  • ASCAT CN/purity input QA／compatibility checks。
  • C++ annealed SMC backend。
  • q-baseline diagnostic artifacts，包括 topology、CCF、assignment、multiplicity output。
  • workflow-level diagnostics 與 fail-closed gates。
文件 target/spec
  • PhyClone phyclone_xi_v1。
  • error_rate=0.001。
  • genotype CN-timing candidates 與完整 candidate marginalization。
  • predicted_xi 與 runtime metadata。
目前不能宣稱
  • 任一棵 candidate tree 是唯一真實樹。
  • PhyClone xi 已被 C++ runtime 使用。
  • VAF predictive gate 已通過。
  • formal high-confidence biological conclusion。

目前最準確的總結：資料介面與 SMC backend 已能運作；但 PhyClone VAF/error-rate 尚未同步到 runtime，validation 仍是 scaffold／workflow diagnostics，最新 output 不是 biological truth，而是 diagnostic candidate output。

07 · 快速定位問題

遇到問題時，要找哪個模組？

問題描述責任模組原因
reads、CN、purity 欄位不對data input輸入 contract 或 provenance 出錯。
q、likelihood、VAF 公式不對model模型的數學定義或 emission 出錯。
候選 tree 太相似、ESS 太低inference_algo + workflowinference 改善探索；workflow 執行 gate 並在不足時停止。
CCF、assignment、artifact 解讀錯output模型參數轉成研究結果時出錯。
repeat 不穩、不能正式宣稱validation + workflowvalidation 評估證據與 claim ceiling；workflow 負責阻擋未通過的 stage。
receipt、QA、停止條件遺失experiment_workflow流程編排與稽核紀錄出錯。
